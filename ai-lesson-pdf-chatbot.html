Week 2 · extends Subject 8

Build: the PDF chatbot, end to end

Build the complete project step by step: load a PDF, chunk it, index it, retrieve, answer with citations, refuse when unsure, test it with a golden set and put a chat interface on it.

Download the starter project (code)Quiz and answer keyClickable handbook
In plain words. A librarian with a photographic index. You ask a question; the librarian finds the three most relevant cards, reads them, answers in their own words and tells you the page. If no card fits, they say so instead of inventing.

1. Why it matters

  • This is the portfolio project most AI job postings describe: RAG over company documents.
  • It uses every Week 1 and Week 2 skill: Python, APIs, prompts, chunking, embeddings and retrieval.
  • It becomes the base for the capstone: add agents, evaluation and deployment on top.

2. Key ideas

IngestionLoad the PDF, extract text per page, chunk it and store chunks with file and page metadata.
IndexThe vector store: chunk text, embedding and metadata. Built once, saved, reused.
RetrievalEmbed the question and fetch the top k chunks by cosine similarity.
Grounded promptNumbered sources plus the question, with rules: use only the sources, cite them, refuse otherwise.
Citations to pagesEach [Sn] tag maps back to file and page so the UI can show where an answer came from.
Golden setQuestions with expected answers and pages, including questions the document cannot answer and attack prompts.

3. How it works, step by step

Upload PDF→Chunk + embed→Vector store→Question→Top-k sources→Claude + rules→Answer [S1] p.2
  1. Download the starter project and run pytest; all tests pass offline.
  2. Read starter/rag.py: index_pdf (load, chunk, embed, store) and answer (check, retrieve, gate, prompt, model, check, log).
  3. Run examples/l6_pdf_chatbot.py on the sample policy and read each answer, citation and refusal.
  4. Replace data/sample_policy.pdf with your own PDF and write 15 golden questions for it in evals/golden.jsonl.
  5. Run python evals/run_evals.py; fix the lowest score first (usually chunking or the retrieval threshold).
  6. Add your API key to .env and run again; compare offline and Claude answers for the same questions.
  7. Start the Streamlit app, upload your PDF and record a two-minute demo for your portfolio.

4. Code you can run

Run it from the starter project folder: python examples/l6_pdf_chatbot.py. It runs offline for free; add an API key in .env to use Claude.

starter/rag.py (in the starter project)
"""The PDF chatbot pipeline: index a PDF, retrieve chunks, answer with citations, refuse
when the documents do not cover the question."""
from .chunking import recursive
from .config import settings
from .costs import Timer, request_cost
from .guardrails import check_injection, grounded, redact_pii
from .llm import chat
from .ops import get_prompt, log_request
from .pdf_loader import load_pdf
from .store import VectorStore

PROMPT_VERSION = "rag-answer@v2"
DONT_KNOW = "I don't know. The documents I was given do not answer this question."


def index_pdf(path: str, store: VectorStore | None = None, max_words: int = 80) -> VectorStore:
    store = store or VectorStore()
    name = path.replace("\\", "/").split("/")[-1]
    for page in load_pdf(path):
        chunks = recursive(page["text"], max_words=max_words, meta={"file": name, "page": page["page"]})
        for c in chunks:
            c.id = f"{name}-p{page['page']}-{c.id}"
        store.add(chunks)
    return store


def build_prompt(question: str, hits: list[dict]) -> str:
    sources = "\n".join(f"[S{i + 1}] {h['text']}" for i, h in enumerate(hits))
    return f"SOURCES:\n{sources}\n\nQUESTION: {question}"


def answer(store: VectorStore, question: str, k: int = 3, log: bool = True) -> dict:
    timer = Timer()
    ok, why = check_injection(question)
    if not ok:
        return {"answer": "I can't help with that request.", "sources": [], "blocked": why}
    with timer.part("retrieve"):
        hits = store.search(question, k=k)
    if not hits or hits[0]["score"] < settings.min_retrieval_score:
        result = {"answer": DONT_KNOW, "sources": [], "refused": True, "top_score": round(hits[0]["score"], 3) if hits else 0}
    else:
        with timer.part("generate"):
            reply = chat(get_prompt(PROMPT_VERSION), build_prompt(question, hits))
        text, _ = redact_pii(reply.text)
        is_grounded, share = grounded(text, [h["text"] for h in hits])
        result = {
            "answer": text,
            "sources": [{"tag": f"S{i + 1}", "file": h["meta"].get("file"), "page": h["meta"].get("page"), "score": round(h["score"], 3)} for i, h in enumerate(hits)],
            "grounded": is_grounded, "grounded_share": share,
            "tokens": {"input": reply.input_tokens, "output": reply.output_tokens},
            "cost_usd": round(request_cost(reply.input_tokens, reply.output_tokens), 6),
            "model": reply.model, "refused": text.startswith("I don't know"),
        }
    result["timings_ms"] = {k: round(v * 1000, 2) for k, v in timer.parts.items()}
    if log:
        log_request(settings.log_path, question=question, prompt_version=PROMPT_VERSION, answer=result["answer"],
                    sources=[s["tag"] + ":" + str(s["page"]) for s in result.get("sources", [])],
                    refused=result.get("refused", False), timings_ms=result["timings_ms"], tokens=result.get("tokens"))
    return result

5. What the code does

  • index_pdf loads each page, chunks it recursively and keeps file and page in the chunk metadata.
  • answer checks for injection, retrieves k chunks, refuses below the score threshold, builds the numbered prompt and calls the model.
  • After the call it removes personal data, checks groundedness, maps tags to pages, adds tokens and cost, and logs the request.
  • The run above shows answers with page citations, a refusal for parental leave (not in the document) and a blocked injection.
  • In offline mode the answer is the best-matching sentence. With a key, Claude writes the answer from the same sources.

6. Common mistakes and fixes

ProblemFix
Answers cite the wrong pageCheck that page metadata survives chunking; print the hits for a failing question.
Every question is refusedThe retrieval threshold is too high for your embedding; tune MIN_RETRIEVAL_SCORE on the golden set.
Answers mix sources from different documentsAdd a document filter or show the document name in each source.
Slow start-up with large PDFsSave the index (VectorStore.save) and load it instead of rebuilding.
Good offline, worse with the modelRead the prompt version and the sources sent; the model follows the rules you give it, so check them.

7. Product manager view

  • Define success before building: answer accuracy, citation accuracy, refusal correctness and p95 latency targets.
  • Pick documents with a clear owner who will keep them current; stale documents produce confident wrong answers.
  • Plan the hand-off: what the bot offers when it refuses (a link, a form, a person).

8. Assignment

Build the chatbot on a public PDF of your choice (a policy, a manual, a government scheme). Deliver: the repository, golden set of at least 15 questions with results, a screenshot or video of the app, and a README with an architecture diagram and your evaluation numbers.

Check your work against the model answer for Subject 8.

9. Interview questions

Walk me through your RAG chatbot.

Ingestion (load, chunk with metadata, embed, store), query time (embed question, retrieve top k, gate on score, grounded prompt with citations, model call, output checks), and evaluation (golden set with answer, citation and refusal metrics).

How do you know your chatbot is good?

A golden set from real questions with expected answers and pages, including unanswerable and attack questions, scored on every change, plus a weekly sample of live answers.

What would you change to support 10,000 documents?

A real embedding model and a vector database with metadata filters, hybrid search with reranking, incremental indexing, access control on chunks and caching.
