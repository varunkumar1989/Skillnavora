Subject 1: Python for AI beginners

Covered on the website   Week 1 · Mandatory foundation

1. Understand

Python is a language you write as short, plain instructions. Think of a recipe: each line is one step, and the cook (the computer) follows them in order.

2. Why it matters

Almost every AI tool, library and API example you will meet is written in Python. You do not need to be a programmer to read and change it, but you need the basics.

3. How it works

  • Install Python 3.12 or newer from python.org, then check with python --version.
  • Install VS Code and the Python extension.
  • Learn variables, numbers, strings, lists, dictionaries, if-statements, loops and functions.
  • Use a virtual environment for each project (python -m venv .venv), so libraries do not clash.
  • Keep your code in Git and GitHub from day one.

4. Practical implementation

File: tools/aihandbook/examples/01_calculator.py

# Week 1, Subject 1: variables, input, if-statements, functions
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        return "Cannot divide by zero"
    return a / b

print("2 + 3 =", add(2, 3))
print("10 / 4 =", divide(10, 4))
print("10 / 0 =", divide(10, 0))

Expected output (produced by running the file)

2 + 3 = 5
10 / 4 = 2.5
10 / 0 = Cannot divide by zero

5. Code explained

  • def add(a, b): defines a reusable function with two inputs.
  • return sends a value back to the caller.
  • if b == 0 protects against dividing by zero: a 'guard'. Guards make programs safer.

5b. Deep dive

Think of a Python file as a list of instructions run from top to bottom. Each line either stores a value (x = 5), changes the flow (if, for), or calls a function that does a job. Indentation is not decoration: Python uses it to know which lines belong to a block.

A function is a named, reusable recipe. Write it once, call it many times. Parameters are the ingredients you pass in; return is the dish you get back. A function with no return gives back None, a frequent beginner bug.

A virtual environment (.venv) keeps one project's libraries separate from another's. Create it with python -m venv .venv, activate it, then install with pip install. Commit requirements.txt (from pip freeze) so anyone can rebuild the same environment.

Errors are information. Read the last line of a traceback first (the error type and message), then the line number above it. Use print() or the VS Code debugger to inspect values before guessing.

6. Testing

Run the file. The three printed lines must match the expected output above.

7. Troubleshooting

  • 'python' not found: on Windows try 'py', or reinstall with 'Add to PATH' ticked.
  • IndentationError: Python uses indentation to group lines. Use 4 spaces, not a mix of tabs and spaces.

8. AI Product Manager perspective

  • You will not write most AI code yourself, but you will read it. Knowing what a function, an error and a dependency are lets you ask better questions of engineers.

9. Assignment

Write a function that takes a list of monthly expenses and returns the average, with a guard for an empty list. Save it in a Git repository with a README.

10. Interview preparation

Q: What is a virtual environment and why use one?
An isolated folder of libraries for one project, so versions of packages do not conflict between projects.

Subject 2: APIs and backend fundamentals

Covered on the website   Week 1 · Mandatory foundation

1. Understand

An API is a waiter. You (the app) tell the waiter what you want from the kitchen (the server). The waiter brings back the answer in a standard format, usually JSON.

2. Why it matters

Every LLM provider (OpenAI, Anthropic, Google) is reached through an API. Knowing requests, responses and status codes lets you debug any AI integration.

3. How it works

  • Learn the flow: USER -> FRONTEND -> BACKEND -> API -> SERVER -> RESPONSE.
  • Learn the methods: GET reads, POST creates, PUT replaces, PATCH changes part, DELETE removes.
  • Learn the status codes: 200 OK, 400 bad request, 401 wrong key, 429 too many requests, 500 server error.
  • Store secrets in environment variables, never in code.
  • Try an API in Postman, then in Python with the requests library.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Headers carry metadata such as the key (Authorization) and the content type.
  • The body carries the data, usually JSON.
  • A 429 means you hit a rate limit: wait, then retry with backoff.

5b. Deep dive

A request has four parts: the method (GET, POST...), the URL (where), the headers (metadata, such as the key), and the body (the data, usually JSON). A response has a status code, headers and a body.

Status code families: 2xx success, 3xx redirect, 4xx the client made a mistake (400 bad input, 401 missing or wrong key, 403 not allowed, 404 not found, 429 too many requests), 5xx the server failed (500, 503). Log the status and the first 200 characters of the body when an API call fails.

Secrets: never paste an API key into code, a notebook or a chat. Put it in an environment variable (for example OPENAI_API_KEY) and read it with os.environ. Rotate the key if it was ever shared.

Rate limits and retries: providers limit calls per minute and per day. Retry only on 429 and 5xx, wait longer each time (exponential backoff: 1s, 2s, 4s), and stop after a few tries.

6. Testing

Call a public test API in Postman and confirm you get 200 with JSON back.

7. Troubleshooting

  • 401: check the key and the header name.
  • 429: slow down, batch requests, or check your plan limits.
  • Timeouts: set a timeout in your code so the app does not hang.

8. AI Product Manager perspective

  • Rate limits, latency and error handling are product decisions as much as engineering ones. Ask: what does the user see when the API is down?

9. Assignment

Use the requests library to call a free public API and print three fields from the JSON response.

10. Interview preparation

Q: What does a 429 status code mean?
Too many requests: the client has exceeded a rate limit and should wait and retry, usually with exponential backoff.

Subject 3: LLM and generative AI fundamentals

Covered on the website   Week 1 · Mandatory foundation

1. Understand

A large language model predicts the next word (token) many times over. Like autocomplete on a phone, but trained on a huge amount of text, so the predictions form sentences, code and reasoning.

2. Why it matters

If you know how the model works, you can predict its failures: it can invent facts (hallucinate), forget far-back text (context window limits) and change answers with settings (temperature).

3. How it works

  • Tokens: text is split into pieces. 'Hallucination' may be 3 tokens. Costs and limits are counted in tokens.
  • Embeddings: each token is turned into a list of numbers that places similar meanings close together.
  • Transformers and attention: the model looks at all earlier tokens and decides which ones matter for the next word.
  • Training (pre-training) builds the model; inference is when you use it.
  • Temperature: 0 is focused and repeatable, higher is more varied.
  • System prompt: standing instructions. User prompt: the request. Structured output: ask for JSON.

4. Practical implementation

File: tools/aihandbook/examples/02_json_tokens.py

# Week 1, Subject 4 and 21: dictionaries, lists, JSON
import json

message = {
    "role": "user",
    "content": "Summarise this policy in 3 bullets",
}
conversation = [
    {"role": "system", "content": "You are a helpful assistant."},
    message,
]
text = json.dumps(conversation, indent=2)
print(text)

# A very rough token estimate: about 4 characters per token in English
estimate = len(text) // 4
print("Rough token estimate:", estimate)

Expected output (produced by running the file)

[
  {
    "role": "system",
    "content": "You are a helpful assistant."
  },
  {
    "role": "user",
    "content": "Summarise this policy in 3 bullets"
  }
]
Rough token estimate: 40

5. Code explained

  • json.dumps turns Python objects into text that an API can receive.
  • The 'role' field tells the model who is speaking: system, user or assistant.
  • The token estimate is only a rough guide. Use the provider's tokenizer for exact counts.

5b. Deep dive

Tokens are not words. 'Unbelievable' may split into several tokens. Rule of thumb for English: roughly 4 characters or three-quarters of a word per token, but always measure with the provider's own tokenizer or usage field.

The context window is the model's working memory: instructions, conversation history, retrieved text and the answer all share it. When it fills up, older text is cut off or must be summarised.

Attention lets each token weigh the other tokens. In 'The bank by the river', attention helps the model link 'bank' to 'river' rather than to money. The original paper is Attention Is All You Need (2017).

Temperature rescales the probabilities of the next token. At 0 the model almost always picks the most likely token; at 1 it samples more widely. Top-p limits sampling to the most likely tokens that add up to a threshold.

Hallucinations come from the training objective: predict likely text. A fluent wrong answer is therefore a normal failure mode, not a rare bug. Design for it with sources, refusals and checks.

6. Testing

Run the file and check the JSON structure and the token estimate.

7. Troubleshooting

  • Answers change every run: set temperature to 0 for repeatable tests.
  • Long conversations get cut off: you have exceeded the context window; summarise older turns.

8. AI Product Manager perspective

  • Model choice is a trade-off of quality, speed, cost and privacy. Start with the cheapest model that passes your evaluation set, then upgrade only where quality demands it.

9. Assignment

Explain in 150 words, to a non-technical manager, why an LLM can sound confident and still be wrong. Use the words token and training.

10. Interview preparation

Q: What is a token?
A piece of text (a word, part of a word or punctuation) that the model reads and produces. Usage and cost are measured in tokens.

Q: What is temperature?
A setting that controls randomness in sampling: lower values give more predictable output.

Subject 4: LLM API integration: your first AI application

Covered on the website   Week 1 · Mandatory foundation

1. Understand

Calling an LLM API is a request-response conversation. You send a list of messages; the model returns one reply. Your app decides what to do with it.

2. Why it matters

This is the smallest possible AI product: input, model, output. Every bigger system (RAG, agents) is this call plus extra steps.

3. How it works

  • Choose a provider and create an API key in its console. Store it in an environment variable.
  • Install the official SDK (for example the openai or anthropic package) and read its current documentation.
  • Send system and user messages. Read the text from the response object.
  • Keep conversation history by appending each message to a list.
  • Handle errors (timeouts, rate limits, invalid keys) and log token usage.

4. Practical implementation

File: tools/aihandbook/examples/03_fake_llm_call.py

# Week 1, Subject 4: the shape of an LLM call, tested offline with a fake model
def fake_llm(messages, temperature=0.0):
    # A real provider returns text generated by a model. This stand-in just echoes the last user message.
    last = messages[-1]["content"]
    return f"(model answer to: {last})"

def ask(question, system="You are concise."):
    messages = [
        {"role": "system", "content": system},
        {"role": "user", "content": question},
    ]
    answer = fake_llm(messages, temperature=0.2)
    return answer

print(ask("What is an API?"))

Expected output (produced by running the file)

(model answer to: What is an API?)

5. Code explained

  • ask() builds the message list: the system message sets behaviour, the user message is the question.
  • fake_llm stands in for the real SDK call, so the lesson works without a key.
  • Swap fake_llm for the real SDK call when you have a key; the rest of the code stays the same.

5b. Deep dive

A chat request is a list of messages with roles. The system message sets rules, the user message is the request, and assistant messages are earlier replies. Keep the list short: send only the turns that matter.

Streaming sends tokens as they are generated. It improves perceived speed; total time is similar. Use it for chat screens; use normal calls for batch jobs.

Structured output: ask for JSON with named keys, validate it in code, and retry or reject if it does not parse. Never trust free text to be parseable.

Cost = input tokens x input price + output tokens x output price. Track both per request, and set a monthly budget alert in the provider console.

6. Testing

Run the file; the output must show your question inside the answer.

7. Troubleshooting

  • Empty answer: print the full response object to see the error.
  • Costs rising: log tokens per request and set a monthly budget alert in the provider console.

8. AI Product Manager perspective

  • Track cost per successful task, not cost per call. A cheap call that fails is expensive.

9. Assignment

Build a command-line app: the user types a question, the app calls an LLM (or fake_llm), prints the answer, and quits on the word exit.

10. Interview preparation

Q: What is the difference between a system message and a user message?
The system message sets the model's role and rules; the user message is the request for this turn.
