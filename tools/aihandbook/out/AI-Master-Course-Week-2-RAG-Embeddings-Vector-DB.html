Subject 5: Understanding RAG (retrieval-augmented generation)

Covered on the website   Week 2 · Core practical skills

1. Understand

RAG is an open-book exam. Before the model answers, your app looks up the right pages in your documents and hands them to the model with the question.

2. Why it matters

A model only knows what it was trained on. It does not know your leave policy, last week's report or a customer's contract. RAG gives it the right pages at answer time, which is cheaper and easier to update than fine-tuning.

3. How it works

  • Document -> ingestion -> extraction -> chunking -> embedding -> vector database -> retrieval -> LLM -> answer with citations.
  • Use RAG when knowledge changes often or must be cited. Do not use it to teach a new style or skill; that is fine-tuning.
  • Compare with plain search: search returns documents; RAG returns a written answer grounded in them.

4. Practical implementation

File: tools/aihandbook/examples/04_rag_toy.py

# Week 2, Subjects 5-8: chunking, toy embeddings, cosine similarity, top-k retrieval.
# Real systems use an embedding model (a neural network). This toy version counts words,
# so you can see the maths without any API key.
import math, re
from collections import Counter

DOCUMENT = """Employees get 20 days of paid leave per year. Unused leave can be carried forward up to 5 days.
Expense claims must be submitted within 30 days with receipts. Travel is booked through the approved portal.
Remote work is allowed up to 3 days a week with manager approval. Laptops must use disk encryption."""

def chunk(text, size_words=12, overlap=3):
    words = text.split()
    step = size_words - overlap
    return [" ".join(words[i:i + size_words]) for i in range(0, len(words), step)]

def embed(text):
    words = re.findall(r"[a-z]+", text.lower())
    return Counter(words)

def cosine(a, b):
    dot = sum(a[w] * b[w] for w in a)
    na = math.sqrt(sum(v * v for v in a.values()))
    nb = math.sqrt(sum(v * v for v in b.values()))
    return dot / (na * nb) if na and nb else 0.0

def retrieve(question, chunks, k=2):
    q = embed(question)
    scored = [(cosine(q, embed(c)), i, c) for i, c in enumerate(chunks)]
    return sorted(scored, reverse=True)[:k]

chunks = chunk(DOCUMENT)
print("Number of chunks:", len(chunks))
for score, i, text in retrieve("How many days of paid leave do I get?", chunks):
    print(f"score={score:.2f} chunk={i}: {text[:60]}...")

Expected output (produced by running the file)

Number of chunks: 6
score=0.55 chunk=0: Employees get 20 days of paid leave per year. Unused leave c...
score=0.20 chunk=1: Unused leave can be carried forward up to 5 days. Expense cl...

5. Code explained

  • chunk() splits the document into overlapping pieces, so an answer that spans a boundary is not lost.
  • embed() here counts words. A real system uses an embedding model that understands meaning.
  • cosine() measures how similar two vectors are: 1 means the same direction, 0 means unrelated.
  • retrieve() ranks all chunks and returns the top k.

5b. Deep dive

RAG has two halves. Indexing (offline): load documents, chunk, embed, store. Answering (online): embed the question, retrieve top-k chunks, build a prompt with them, call the model, return the answer with sources.

Use RAG when the answer must come from a document that changes, must be cited, or is too large for the context window. Use fine-tuning to change style, format or a narrow skill; use prompting first, because it is the cheapest to try.

Common failure: the right chunk is never retrieved, so the model guesses. Measure retrieval recall before you tune the prompt.

The original RAG idea is described in Lewis et al. (2020), Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks.

6. Testing

Ask a question whose answer is in the document; the top chunk should contain it.

7. Troubleshooting

  • Right answer not retrieved: chunks may be too small or too large; try different sizes and overlap.
  • Answer invents details: the model was not given the chunks, or the prompt did not say 'answer only from the context'.

8. AI Product Manager perspective

  • RAG quality depends on the document pipeline as much as the model. Budget time for document cleaning, and measure retrieval separately from answer quality.

9. Assignment

Change chunk size to 8 and to 20 words. For three questions, record which chunk ranks first each time, and write one sentence on what changed.

10. Interview preparation

Q: When would you choose RAG instead of fine-tuning?
When knowledge changes often, must be cited, or is large. Fine-tuning changes behaviour and style better than it stores facts.

Q: Why do chunks overlap?
So information that sits across a chunk boundary is still fully contained in at least one chunk.

Subject 6: Document processing and chunking

Partial on the website   Week 2 · Core practical skills

1. Understand

Before a model can read a PDF, the text has to be pulled out, cleaned and cut into useful pieces, like preparing ingredients before cooking.

2. Why it matters

Poor chunking is the most common cause of bad RAG answers. If the answer is split across two chunks, retrieval may return only half of it.

3. How it works

  • Extract text from PDFs with a parser; check tables and headers, which often break.
  • Clean: remove repeated headers and footers, fix broken line breaks.
  • Chunk by a fixed size with overlap, by structure (headings, paragraphs) or by meaning (semantic chunking).
  • Attach metadata: file name, page number, section, date, owner.
  • Index every chunk with its metadata so you can cite the source.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Chunk size balances precision (small) against context (large).
  • Overlap protects answers that cross a boundary.
  • Metadata lets you filter ('only the 2026 policy') and cite ('page 4').

5b. Deep dive

Parsing a PDF: text-based PDFs keep text; scanned PDFs are images and need OCR. Tables are the hardest part: extract them as rows with headers, not as loose text, or the columns get mixed up.

Chunk sizes that work well as a starting point are 200 to 500 words with 10 to 20 percent overlap, then tuned with your golden questions. Split on headings or paragraphs first, and only cut inside a paragraph when it is too long.

Metadata is what makes answers trustworthy and filterable: document name, version, date, owner, section, page. Store it with every chunk and return it with every answer.

Document hygiene matters more than model choice: remove duplicates, mark outdated versions as archived, and assign an owner to every source.

6. Testing

Pick ten facts from the document and check that each one can be found in a single chunk.

7. Troubleshooting

  • Garbled text: the PDF may be scanned; use OCR.
  • Table answers are wrong: convert tables to text rows with headers before chunking.

8. AI Product Manager perspective

  • Ask who owns document quality. Stale or duplicate documents cause confident wrong answers, which is a product risk, not only a technical one.

9. Assignment

Take one real PDF (a public policy or report). Extract, clean and chunk it. Write a table of 10 facts and the chunk where each one appears.

10. Interview preparation

Q: What is chunk overlap?
Repeating some text between neighbouring chunks so answers that span a boundary are not split.

Subject 7: Embeddings and vector databases

Covered on the website   Week 2 · Core practical skills

1. Understand

An embedding is a map coordinate for meaning. Sentences with similar meaning get nearby coordinates, even if they share no words.

2. Why it matters

Keyword search misses 'annual leave' when the document says 'paid time off'. Embeddings find it because the meaning is close.

3. How it works

  • Choose an embedding model from a provider or an open-source model; check its dimension and cost.
  • Store vectors in a vector database (FAISS for local work, Chroma for simple apps, Qdrant or pgvector for production, Pinecone as a managed service).
  • Search with cosine similarity and top-k; add metadata filters.
  • Use hybrid search (keywords + vectors) and a reranker to improve the top results.
  • Measure precision (are the results relevant?) and recall (did we find everything relevant?).

4. Practical implementation

File: tools/aihandbook/examples/04_rag_toy.py

5. Code explained

  • Cosine similarity compares direction, so long and short texts can still match.
  • Top-k returns the k best matches; k is a trade-off between coverage and noise.
  • Recommendation for beginners: Chroma for learning, pgvector when you already run PostgreSQL.

5b. Deep dive

An embedding model turns a text into a vector, often of 384 to 3072 numbers. Compare vectors with cosine similarity. The model and its dimension must be the same for documents and queries.

Vector databases store the vectors and find the nearest ones quickly. Options: FAISS (a library for local search, very fast), Chroma (simple Python API for learning and small apps), pgvector (vectors inside PostgreSQL, good when you already run Postgres), Qdrant and Pinecone (servers or managed services for scale).

Hybrid search combines keyword scores (BM25) with vector scores. It helps with product codes, names and exact phrases that embeddings can blur.

Reranking: a stronger model re-scores the top 20 to 50 chunks and keeps the best 3 to 5. It costs time and money, so measure whether it improves answers.

6. Testing

For 10 test questions, check that the right chunk is in the top 3 results (recall at 3).

7. Troubleshooting

  • Results look random: check you use the same embedding model for documents and queries.
  • Results miss obvious matches: add hybrid search or a reranker.

8. AI Product Manager perspective

  • Vector search adds cost and an index to maintain. Ask whether a simple keyword search meets the need before adding it.

9. Assignment

Compare keyword matching and the toy embedding on five questions with synonyms (e.g. 'holiday' vs 'leave'). Report which method finds more correct chunks.

10. Interview preparation

Q: What is cosine similarity?
A measure of the angle between two vectors. Values near 1 mean very similar meaning in embedding space.

Q: What is hybrid search?
Combining keyword (lexical) search with vector (semantic) search, then merging the results.

Subject 8: Project: PDF-based RAG chatbot

Gap on the website   Week 2 · Core practical skills

1. Understand

You will build a chatbot that answers questions about your own PDFs and shows where each answer came from.

2. Why it matters

This is the most requested first AI product in companies: internal policy bots, sales-enablement assistants and support knowledge bases.

3. How it works

  • Step 1: upload PDFs and extract text.
  • Step 2: chunk with metadata.
  • Step 3: embed and store.
  • Step 4: retrieve top-k for each question.
  • Step 5: build the prompt: instructions + retrieved chunks + question.
  • Step 6: call the LLM, return the answer and the source list.
  • Step 7: if nothing relevant is retrieved, say you do not know rather than guessing.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • The prompt must tell the model to use only the supplied context and to cite chunk numbers.
  • The 'I do not know' path is a feature: it protects users from confident wrong answers.

5b. Deep dive

Architecture of the project: a loader module (PDF to text), a chunker, an embedding function, a store, a retriever, a prompt builder, an answer function and a small web interface (Streamlit).

Prompt pattern: 'Answer only from the sources. Cite the source id for each claim. If the sources do not contain the answer, say you do not know and suggest who to ask.' Test that the bot follows it with questions that have no answer in the documents.

Evaluation before polish: 20 golden questions, five with no answer in the documents. Track answer correctness, citation correctness and refusal correctness separately.

6. Testing

Ask 10 questions: 5 answerable from the PDFs and 5 not. The bot must answer the first five with citations and decline the last five.

7. Troubleshooting

  • Good chunks, bad answer: tighten the prompt and reduce the number of chunks.
  • Wrong citations: check the chunk IDs in the prompt match the metadata you return.

8. AI Product Manager perspective

  • Define 'good' before building: target answer accuracy, citation rate and how often the bot should refuse.

9. Assignment

Deliver the chatbot with a README, 10 test questions and a short report of what failed and how you fixed it.

10. Interview preparation

Q: How do you stop a RAG bot making things up?
Ground answers in retrieved text, instruct it to cite and to refuse when context is missing, and evaluate refusals as well as answers.
