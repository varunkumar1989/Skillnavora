Each subject follows the same eleven steps: understand (analogy), why it matters, how it works, practical implementation, code explained, testing, troubleshooting, product perspective, assignment, interview questions and further reading.

Rule for every topic: reading an explanation does not count as learning it. Run the code, change it, and show your result.
Check before you rely on a tool: AI tools, model names, prices and free limits change often. Confirm them on the provider's official page the day you use them.

Code examples are real. The six example files in tools/aihandbook/examples run without an API key, and the outputs in this handbook were produced by running them when the handbook was built.

Subject 1: Python for AI beginners

Covered on the website   Week 1 · Mandatory foundation

1. Understand

Python is a language you write as short, plain instructions. Think of a recipe: each line is one step, and the cook (the computer) follows them in order.

2. Why it matters

Almost every AI tool, library and API example you will meet is written in Python. You do not need to be a programmer to read and change it, but you need the basics.

3. How it works

  • Install Python 3.12 or newer from python.org, then check with python --version.
  • Install VS Code and the Python extension.
  • Learn variables, numbers, strings, lists, dictionaries, if-statements, loops and functions.
  • Use a virtual environment for each project (python -m venv .venv), so libraries do not clash.
  • Keep your code in Git and GitHub from day one.

4. Practical implementation

File: tools/aihandbook/examples/01_calculator.py

# Week 1, Subject 1: variables, input, if-statements, functions
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        return "Cannot divide by zero"
    return a / b

print("2 + 3 =", add(2, 3))
print("10 / 4 =", divide(10, 4))
print("10 / 0 =", divide(10, 0))

Expected output (produced by running the file)

2 + 3 = 5
10 / 4 = 2.5
10 / 0 = Cannot divide by zero

5. Code explained

  • def add(a, b): defines a reusable function with two inputs.
  • return sends a value back to the caller.
  • if b == 0 protects against dividing by zero: a 'guard'. Guards make programs safer.

6. Testing

Run the file. The three printed lines must match the expected output above.

7. Troubleshooting

  • 'python' not found: on Windows try 'py', or reinstall with 'Add to PATH' ticked.
  • IndentationError: Python uses indentation to group lines. Use 4 spaces, not a mix of tabs and spaces.

8. AI Product Manager perspective

  • You will not write most AI code yourself, but you will read it. Knowing what a function, an error and a dependency are lets you ask better questions of engineers.

9. Assignment

Write a function that takes a list of monthly expenses and returns the average, with a guard for an empty list. Save it in a Git repository with a README.

10. Interview preparation

Q: What is a virtual environment and why use one?
An isolated folder of libraries for one project, so versions of packages do not conflict between projects.

Subject 2: APIs and backend fundamentals

Covered on the website   Week 1 · Mandatory foundation

1. Understand

An API is a waiter. You (the app) tell the waiter what you want from the kitchen (the server). The waiter brings back the answer in a standard format, usually JSON.

2. Why it matters

Every LLM provider (OpenAI, Anthropic, Google) is reached through an API. Knowing requests, responses and status codes lets you debug any AI integration.

3. How it works

  • Learn the flow: USER -> FRONTEND -> BACKEND -> API -> SERVER -> RESPONSE.
  • Learn the methods: GET reads, POST creates, PUT replaces, PATCH changes part, DELETE removes.
  • Learn the status codes: 200 OK, 400 bad request, 401 wrong key, 429 too many requests, 500 server error.
  • Store secrets in environment variables, never in code.
  • Try an API in Postman, then in Python with the requests library.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Headers carry metadata such as the key (Authorization) and the content type.
  • The body carries the data, usually JSON.
  • A 429 means you hit a rate limit: wait, then retry with backoff.

6. Testing

Call a public test API in Postman and confirm you get 200 with JSON back.

7. Troubleshooting

  • 401: check the key and the header name.
  • 429: slow down, batch requests, or check your plan limits.
  • Timeouts: set a timeout in your code so the app does not hang.

8. AI Product Manager perspective

  • Rate limits, latency and error handling are product decisions as much as engineering ones. Ask: what does the user see when the API is down?

9. Assignment

Use the requests library to call a free public API and print three fields from the JSON response.

10. Interview preparation

Q: What does a 429 status code mean?
Too many requests: the client has exceeded a rate limit and should wait and retry, usually with exponential backoff.

Subject 3: LLM and generative AI fundamentals

Covered on the website   Week 1 · Mandatory foundation

1. Understand

A large language model predicts the next word (token) many times over. Like autocomplete on a phone, but trained on a huge amount of text, so the predictions form sentences, code and reasoning.

2. Why it matters

If you know how the model works, you can predict its failures: it can invent facts (hallucinate), forget far-back text (context window limits) and change answers with settings (temperature).

3. How it works

  • Tokens: text is split into pieces. 'Hallucination' may be 3 tokens. Costs and limits are counted in tokens.
  • Embeddings: each token is turned into a list of numbers that places similar meanings close together.
  • Transformers and attention: the model looks at all earlier tokens and decides which ones matter for the next word.
  • Training (pre-training) builds the model; inference is when you use it.
  • Temperature: 0 is focused and repeatable, higher is more varied.
  • System prompt: standing instructions. User prompt: the request. Structured output: ask for JSON.

4. Practical implementation

File: tools/aihandbook/examples/02_json_tokens.py

# Week 1, Subject 4 and 21: dictionaries, lists, JSON
import json

message = {
    "role": "user",
    "content": "Summarise this policy in 3 bullets",
}
conversation = [
    {"role": "system", "content": "You are a helpful assistant."},
    message,
]
text = json.dumps(conversation, indent=2)
print(text)

# A very rough token estimate: about 4 characters per token in English
estimate = len(text) // 4
print("Rough token estimate:", estimate)

Expected output (produced by running the file)

[
  {
    "role": "system",
    "content": "You are a helpful assistant."
  },
  {
    "role": "user",
    "content": "Summarise this policy in 3 bullets"
  }
]
Rough token estimate: 40

5. Code explained

  • json.dumps turns Python objects into text that an API can receive.
  • The 'role' field tells the model who is speaking: system, user or assistant.
  • The token estimate is only a rough guide. Use the provider's tokenizer for exact counts.

6. Testing

Run the file and check the JSON structure and the token estimate.

7. Troubleshooting

  • Answers change every run: set temperature to 0 for repeatable tests.
  • Long conversations get cut off: you have exceeded the context window; summarise older turns.

8. AI Product Manager perspective

  • Model choice is a trade-off of quality, speed, cost and privacy. Start with the cheapest model that passes your evaluation set, then upgrade only where quality demands it.

9. Assignment

Explain in 150 words, to a non-technical manager, why an LLM can sound confident and still be wrong. Use the words token and training.

10. Interview preparation

Q: What is a token?
A piece of text (a word, part of a word or punctuation) that the model reads and produces. Usage and cost are measured in tokens.

Q: What is temperature?
A setting that controls randomness in sampling: lower values give more predictable output.

Subject 4: LLM API integration: your first AI application

Covered on the website   Week 1 · Mandatory foundation

1. Understand

Calling an LLM API is a request-response conversation. You send a list of messages; the model returns one reply. Your app decides what to do with it.

2. Why it matters

This is the smallest possible AI product: input, model, output. Every bigger system (RAG, agents) is this call plus extra steps.

3. How it works

  • Choose a provider and create an API key in its console. Store it in an environment variable.
  • Install the official SDK (for example the openai or anthropic package) and read its current documentation.
  • Send system and user messages. Read the text from the response object.
  • Keep conversation history by appending each message to a list.
  • Handle errors (timeouts, rate limits, invalid keys) and log token usage.

4. Practical implementation

File: tools/aihandbook/examples/03_fake_llm_call.py

# Week 1, Subject 4: the shape of an LLM call, tested offline with a fake model
def fake_llm(messages, temperature=0.0):
    # A real provider returns text generated by a model. This stand-in just echoes the last user message.
    last = messages[-1]["content"]
    return f"(model answer to: {last})"

def ask(question, system="You are concise."):
    messages = [
        {"role": "system", "content": system},
        {"role": "user", "content": question},
    ]
    answer = fake_llm(messages, temperature=0.2)
    return answer

print(ask("What is an API?"))

Expected output (produced by running the file)

(model answer to: What is an API?)

5. Code explained

  • ask() builds the message list: the system message sets behaviour, the user message is the question.
  • fake_llm stands in for the real SDK call, so the lesson works without a key.
  • Swap fake_llm for the real SDK call when you have a key; the rest of the code stays the same.

6. Testing

Run the file; the output must show your question inside the answer.

7. Troubleshooting

  • Empty answer: print the full response object to see the error.
  • Costs rising: log tokens per request and set a monthly budget alert in the provider console.

8. AI Product Manager perspective

  • Track cost per successful task, not cost per call. A cheap call that fails is expensive.

9. Assignment

Build a command-line app: the user types a question, the app calls an LLM (or fake_llm), prints the answer, and quits on the word exit.

10. Interview preparation

Q: What is the difference between a system message and a user message?
The system message sets the model's role and rules; the user message is the request for this turn.

Subject 5: Understanding RAG (retrieval-augmented generation)

Covered on the website   Week 2 · Core practical skills

1. Understand

RAG is an open-book exam. Before the model answers, your app looks up the right pages in your documents and hands them to the model with the question.

2. Why it matters

A model only knows what it was trained on. It does not know your leave policy, last week's report or a customer's contract. RAG gives it the right pages at answer time, which is cheaper and easier to update than fine-tuning.

3. How it works

  • Document -> ingestion -> extraction -> chunking -> embedding -> vector database -> retrieval -> LLM -> answer with citations.
  • Use RAG when knowledge changes often or must be cited. Do not use it to teach a new style or skill; that is fine-tuning.
  • Compare with plain search: search returns documents; RAG returns a written answer grounded in them.

4. Practical implementation

File: tools/aihandbook/examples/04_rag_toy.py

# Week 2, Subjects 5-8: chunking, toy embeddings, cosine similarity, top-k retrieval.
# Real systems use an embedding model (a neural network). This toy version counts words,
# so you can see the maths without any API key.
import math, re
from collections import Counter

DOCUMENT = """Employees get 20 days of paid leave per year. Unused leave can be carried forward up to 5 days.
Expense claims must be submitted within 30 days with receipts. Travel is booked through the approved portal.
Remote work is allowed up to 3 days a week with manager approval. Laptops must use disk encryption."""

def chunk(text, size_words=12, overlap=3):
    words = text.split()
    step = size_words - overlap
    return [" ".join(words[i:i + size_words]) for i in range(0, len(words), step)]

def embed(text):
    words = re.findall(r"[a-z]+", text.lower())
    return Counter(words)

def cosine(a, b):
    dot = sum(a[w] * b[w] for w in a)
    na = math.sqrt(sum(v * v for v in a.values()))
    nb = math.sqrt(sum(v * v for v in b.values()))
    return dot / (na * nb) if na and nb else 0.0

def retrieve(question, chunks, k=2):
    q = embed(question)
    scored = [(cosine(q, embed(c)), i, c) for i, c in enumerate(chunks)]
    return sorted(scored, reverse=True)[:k]

chunks = chunk(DOCUMENT)
print("Number of chunks:", len(chunks))
for score, i, text in retrieve("How many days of paid leave do I get?", chunks):
    print(f"score={score:.2f} chunk={i}: {text[:60]}...")

Expected output (produced by running the file)

Number of chunks: 6
score=0.55 chunk=0: Employees get 20 days of paid leave per year. Unused leave c...
score=0.20 chunk=1: Unused leave can be carried forward up to 5 days. Expense cl...

5. Code explained

  • chunk() splits the document into overlapping pieces, so an answer that spans a boundary is not lost.
  • embed() here counts words. A real system uses an embedding model that understands meaning.
  • cosine() measures how similar two vectors are: 1 means the same direction, 0 means unrelated.
  • retrieve() ranks all chunks and returns the top k.

6. Testing

Ask a question whose answer is in the document; the top chunk should contain it.

7. Troubleshooting

  • Right answer not retrieved: chunks may be too small or too large; try different sizes and overlap.
  • Answer invents details: the model was not given the chunks, or the prompt did not say 'answer only from the context'.

8. AI Product Manager perspective

  • RAG quality depends on the document pipeline as much as the model. Budget time for document cleaning, and measure retrieval separately from answer quality.

9. Assignment

Change chunk size to 8 and to 20 words. For three questions, record which chunk ranks first each time, and write one sentence on what changed.

10. Interview preparation

Q: When would you choose RAG instead of fine-tuning?
When knowledge changes often, must be cited, or is large. Fine-tuning changes behaviour and style better than it stores facts.

Q: Why do chunks overlap?
So information that sits across a chunk boundary is still fully contained in at least one chunk.

Subject 6: Document processing and chunking

Partial on the website   Week 2 · Core practical skills

1. Understand

Before a model can read a PDF, the text has to be pulled out, cleaned and cut into useful pieces, like preparing ingredients before cooking.

2. Why it matters

Poor chunking is the most common cause of bad RAG answers. If the answer is split across two chunks, retrieval may return only half of it.

3. How it works

  • Extract text from PDFs with a parser; check tables and headers, which often break.
  • Clean: remove repeated headers and footers, fix broken line breaks.
  • Chunk by a fixed size with overlap, by structure (headings, paragraphs) or by meaning (semantic chunking).
  • Attach metadata: file name, page number, section, date, owner.
  • Index every chunk with its metadata so you can cite the source.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Chunk size balances precision (small) against context (large).
  • Overlap protects answers that cross a boundary.
  • Metadata lets you filter ('only the 2026 policy') and cite ('page 4').

6. Testing

Pick ten facts from the document and check that each one can be found in a single chunk.

7. Troubleshooting

  • Garbled text: the PDF may be scanned; use OCR.
  • Table answers are wrong: convert tables to text rows with headers before chunking.

8. AI Product Manager perspective

  • Ask who owns document quality. Stale or duplicate documents cause confident wrong answers, which is a product risk, not only a technical one.

9. Assignment

Take one real PDF (a public policy or report). Extract, clean and chunk it. Write a table of 10 facts and the chunk where each one appears.

10. Interview preparation

Q: What is chunk overlap?
Repeating some text between neighbouring chunks so answers that span a boundary are not split.

Subject 7: Embeddings and vector databases

Covered on the website   Week 2 · Core practical skills

1. Understand

An embedding is a map coordinate for meaning. Sentences with similar meaning get nearby coordinates, even if they share no words.

2. Why it matters

Keyword search misses 'annual leave' when the document says 'paid time off'. Embeddings find it because the meaning is close.

3. How it works

  • Choose an embedding model from a provider or an open-source model; check its dimension and cost.
  • Store vectors in a vector database (FAISS for local work, Chroma for simple apps, Qdrant or pgvector for production, Pinecone as a managed service).
  • Search with cosine similarity and top-k; add metadata filters.
  • Use hybrid search (keywords + vectors) and a reranker to improve the top results.
  • Measure precision (are the results relevant?) and recall (did we find everything relevant?).

4. Practical implementation

Outcome: AI research agent

Subject 9: AI agent fundamentals

Covered on the website   Week 3 · Core practical skills

1. Understand

An agent is a chatbot that can act. It loops: think, choose a tool, look at the result, decide the next step, until the task is done.

2. Why it matters

Many business tasks need several steps across systems (check a balance, book a meeting, send an email). An agent can do the steps; you control which tools it may use.

3. How it works

  • Chatbot: one question, one answer. Agent: a loop of decisions and tool calls.
  • Single agent: one model with tools. Multi-agent: several specialised agents hand work to each other.
  • Human-in-the-loop: a person approves risky actions such as sending money or emails.
  • Memory: short-term (this conversation) and long-term (saved facts, retrieved when needed).
  • Limits: wrong tool choices, loops that never end, and costs that grow with each step.

4. Practical implementation

File: tools/aihandbook/examples/05_agent_loop.py

# Week 3, Subjects 9-10: an agent loop with tools, tested with a scripted "model"
import json

TOOLS = {
    "get_leave_balance": lambda employee_id: {"employee_id": employee_id, "days_left": 14},
    "book_meeting": lambda title: {"status": "booked", "title": title},
}

def scripted_model(history):
    # A real model decides the next step. This script shows the decisions it would make.
    if not any(m["role"] == "tool" for m in history):
        return {"action": "tool", "name": "get_leave_balance", "args": {"employee_id": "E42"}}
    return {"action": "final", "text": "You have 14 days of leave left."}

def run_agent(user_request, max_steps=5):
    history = [{"role": "user", "content": user_request}]
    for step in range(max_steps):
        decision = scripted_model(history)
        if decision["action"] == "final":
            return decision["text"]
        result = TOOLS[decision["name"]](**decision["args"])
        history.append({"role": "tool", "content": json.dumps(result)})
        print(f"step {step + 1}: called {decision['name']} -> {result}")
    return "Stopped: step limit reached"

print("Answer:", run_agent("How much leave do I have left?"))

Expected output (produced by running the file)

step 1: called get_leave_balance -> {'employee_id': 'E42', 'days_left': 14}
Answer: You have 14 days of leave left.

5. Code explained

  • TOOLS is a registry: the agent may only call functions listed here.
  • max_steps stops a runaway loop.
  • Each tool result is added to history so the next decision can use it.

6. Testing

Run the file; the agent must call the tool once and then give a final answer.

7. Troubleshooting

  • Agent loops: lower max_steps and make tool descriptions clearer.
  • Wrong tool: improve the tool's name and description, and test each tool separately.

8. AI Product Manager perspective

  • Decide the autonomy level per action: suggest, draft, act with approval, or act automatically. Most enterprise launches start at 'suggest' or 'draft'.

Subject 13: AI evaluation

Covered on the website   Week 4 · Advanced technical knowledge

1. Understand

Evaluation is a driving test for an AI feature. You prepare a fixed set of questions with known good answers, run the system, and count how many it passes.

2. Why it matters

AI output changes when you change a prompt, a model or a document. Without a fixed test set you cannot tell whether a change made things better or worse.

3. How it works

  • Build a golden dataset: 20 or more questions with the expected answer or a checkable fact.
  • Score each answer: correctness, faithfulness (supported by the context), groundedness, retrieval precision and recall.
  • Automate simple checks (must contain a fact, must cite a source).
  • Use LLM-as-a-judge for subjective scores; check the judge against a few human ratings.
  • Re-run the set after every change (regression testing).

4. Practical implementation

File: tools/aihandbook/examples/06_eval_harness.py

# Week 4, Subject 13: a tiny evaluation harness with a golden dataset
GOLDEN = [
    {"question": "How many paid leave days per year?", "must_contain": "20"},
    {"question": "How many days can leave be carried forward?", "must_contain": "5"},
    {"question": "Who approves remote work?", "must_contain": "manager"},
    {"question": "What is the CEO's salary?", "must_contain": "not in the document"},
]

def system_under_test(question):
    answers = {
        "How many paid leave days per year?": "You get 20 days of paid leave.",
        "How many days can leave be carried forward?": "Up to 5 days.",
        "Who approves remote work?": "Your manager approves it.",
        "What is the CEO's salary?": "The CEO earns 5 crore.",  # a hallucination the test should catch
    }
    return answers[question]

passed = 0
for case in GOLDEN:
    answer = system_under_test(case["question"])
    ok = case["must_contain"].lower() in answer.lower()
    passed += ok
    status = "PASS" if ok else "FAIL"
    print(f"{status}  {case['question']}  ->  {answer}")
print(f"Score: {passed}/{len(GOLDEN)} ({passed / len(GOLDEN):.0%})")

Expected output (produced by running the file)

PASS  How many days can leave be carried forward?  ->  Up to 5 days.
PASS  Who approves remote work?  ->  Your manager approves it.
FAIL  What is the CEO's salary?  ->  The CEO earns 5 crore.
Score: 3/4 (75%)

  • GOLDEN is the test set. Keep it in version control.
  • must_contain is the simplest checkable rule.
  • The last case is a deliberate hallucination: the harness must mark it FAIL.

Subject 14: Hallucinations, guardrails and AI quality

Partial on the website   Week 4 · Advanced technical knowledge

1. Understand

A hallucination is a fluent answer that is not supported by the facts. The model is designed to continue text plausibly, not to check truth.

2. Why it matters

In customer support, finance or health, one confident wrong answer can cause real harm. Quality work reduces the chance and limits the damage.

3. How it works

  • Causes: missing context, ambiguous questions, pressure to answer, out-of-date training data.
  • Mitigations: grounding in retrieved sources, citation requirements, refusal when context is missing, confidence signals, fallback answers.
  • Guardrails: input checks (block unsafe requests), output checks (scan for personal data or claims without sources).
  • Prompt injection: instructions hidden in a document or web page that try to override your rules. Treat all retrieved text as untrusted data.
  • Human review: route low-confidence or high-risk answers to a person.

Subject 22: AI product metrics

Partial on the website   Week 6 · AI Product Management skills

1. Understand

Metrics tell you if the product works. For AI you need four families: technical (quality of the model and retrieval), product (use and success), customer (satisfaction), and business (cost and value).

2. Why it matters

A model can score well on accuracy and still fail users if they never adopt it. Each family catches a different failure.

3. How it works

  • Technical: accuracy, hallucination rate, retrieval precision and recall, latency.
  • Product: activation, engagement, task completion, resolution rate, human escalation rate.
  • Customer: satisfaction, complaints, trust rating.
  • Business: cost per task, time saved, revenue or cost impact, ROI.
  • North Star: pick the single metric that best predicts value, for example 'tasks completed correctly per week'.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Choose a metric you can measure every week.
  • Pair quality with cost: a higher-quality model is only better if the extra cost is worth it.

6. Testing

Define 12 metrics (three from each family) with a target and a data source for each.

7. Troubleshooting

  • Metric is not measurable: write how you would collect it.
  • Vanity metrics: if a number cannot change a decision, drop it.

8. AI Product Manager perspective

  • Name the decision each metric informs. If no decision changes, the metric is noise.

9. Assignment

Produce a metrics table for your capstone with North Star, 3 technical, 3 product, 2 customer and 2 business metrics.

10. Interview preparation

Q: What is a North Star metric for an AI support assistant?
Resolution rate with a safe escalation rate: the share of customer issues solved correctly without harm, which captures both value and quality.

G4. User story and acceptance criteria

User story: As a support agent, I want a draft answer with its policy source, so that I can reply to a customer in under two minutes.

Acceptance criteria: (1) every draft cites at least one approved source; (2) answer accuracy is 95% or higher on the golden set; (3) when no source is found, the draft says so and suggests escalation; (4) p95 latency under 8 seconds.

G5. Release gate

No release unless the golden set passes its bar, the risk register is reviewed, the rollback plan is written, and the owner has signed the decision.
