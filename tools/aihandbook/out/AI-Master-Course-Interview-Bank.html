Technical

#AreaQuestionModel answer
1PythonWhat is a virtual environment?An isolated set of libraries for one project, so package versions do not conflict across projects.
2APIsWhat does HTTP status 401 mean?Unauthorised: the key or credentials are missing or wrong.
3APIsWhy use environment variables for keys?They keep secrets out of code and version control, and let each environment use its own values.
4LLMWhat is a token?A piece of text the model reads and writes; usage and cost are counted in tokens.
5LLMWhat is a context window?The maximum number of tokens the model can consider at once, including instructions, history and retrieved text.
6LLMWhat does temperature do?It controls randomness when choosing the next token; lower is more predictable.
7LLMPre-training versus fine-tuning?Pre-training teaches general language from large data; fine-tuning adapts a model to a task or style with a smaller dataset.
8LLMWhat is inference?Running a trained model to produce output for an input.
9PromptingDifference between system and user prompts?The system prompt sets rules and role; the user prompt is the request.
10PromptingHow do you get structured output?Specify a schema, use the provider's structured output or JSON mode, and validate the result in code.
11EmbeddingsWhat is an embedding?A vector of numbers that represents meaning; similar meanings get similar vectors.
12EmbeddingsWhat is cosine similarity?A measure of the angle between two vectors, used to rank semantic similarity.
13RAGWhat is RAG?Retrieval-augmented generation: retrieve relevant passages and give them to the model to answer from.
14RAGWhy does chunk size matter?Too small loses context; too large adds noise and cost and can dilute the answer.
15RAGWhat is reranking?A second model or scorer that reorders retrieved chunks for better relevance before generation.
16Vector DBName two vector databases and when to use each.Chroma for simple local projects; pgvector when PostgreSQL is already in use; Qdrant or Pinecone for scale and managed hosting.
17AgentsWhat is an agent?A system that loops: decides an action, uses a tool, observes the result and continues until the goal is met.
18AgentsHow do you stop an agent looping forever?A step limit, a stop condition, cost budget and timeouts, plus logging of each step.
19ToolsWhat is function calling?The model returns a structured request to call a named function with arguments; your code runs it and returns the result.
20MCPWhat is MCP?Model Context Protocol: an open standard that lets AI apps discover and use tools, resources and prompts from servers.
21EvalsWhat is a golden dataset?A fixed, expert-checked set of test inputs and expected answers used to measure every change.
22EvalsWhat is groundedness?Whether an answer is supported by the provided sources.
23EvalsWhat is LLM-as-a-judge and what are its limits?Using a model to score outputs. It is fast, but can be biased; check it against human ratings.
24HallucinationsWhy do models hallucinate?They generate likely continuations, not verified facts; missing context and ambiguous questions increase the risk.
25SecurityWhat is prompt injection?Hidden instructions in input or retrieved text that try to override the system's rules. Treat retrieved text as untrusted data.
26LatencyWhat drives latency in an LLM app?Retrieval time, prompt length, model size, output length and network calls; measure each part separately.
27CostHow do you reduce LLM cost?Shorter prompts, caching, smaller models for simple steps, routing, batching and limiting output length.
28LLMOpsWhat should you log for each LLM request?Prompt and model versions, retrieved sources, token counts, latency, errors and feedback, with personal data removed.
29ArchitectureHow do you design for failure?Timeouts, retries with backoff, fallback responses, a human handoff and monitoring alerts.
30Responsible AIWhat is human-in-the-loop?A design where a person reviews or approves model output or actions, especially for high-risk decisions.
31PythonWhat is the difference between a list and a dictionary?A list keeps items in order and you reach them by position; a dictionary maps keys to values and you reach them by key. JSON objects become dictionaries in Python.
32PythonWhy use try and except around an API call?Network calls fail for reasons outside your code (timeouts, rate limits, bad keys). Catching specific errors lets you retry, show a clear message or fall back instead of crashing.
33PythonWhat does pip install -r requirements.txt do and why pin versions?It installs every listed package. Pinning versions makes builds repeatable, so a new library release cannot silently break the app.
34PythonWhat is async and when does it help in AI apps?Async lets one process wait on many slow input/output calls at once, such as several model or retrieval calls, instead of waiting for each in turn. It does not speed up heavy computation.
35APIsDifference between GET and POST?GET reads data and sends parameters in the URL; POST sends a body to create something or run an action. Model calls are POST requests because the prompt is in the body.
36APIsWhat does HTTP 429 mean and how do you handle it?Too many requests: you hit a rate limit. Back off and retry with increasing delays, respect any retry-after header, and queue or batch work.
37APIsWhat is the difference between 4xx and 5xx errors?4xx means the request was wrong (bad input, no permission); fix the request. 5xx means the server failed; retrying later can work.
38APIsWhat is idempotency and why does it matter for retries?An idempotent request has the same effect if sent twice. Retrying a non-idempotent action such as a payment can do it twice, so use idempotency keys.
39APIsWhat is streaming in an LLM API?The server sends the answer in pieces as it is generated. Users see text sooner, and long requests avoid time-outs.
40LLMWhat is a transformer, in one sentence?A neural network design that uses attention to weigh how much every token in the input matters to every other token, which lets it model long-range context.
41LLMWhat is attention?A mechanism that lets the model look at all earlier tokens and decide which ones matter most for predicting the next token.
42LLMWhy do longer prompts cost more and run slower?You pay per input token, and the model must process every token before answering. Output tokens are generated one at a time, so long answers are slower still.
43LLMWhat is a system prompt for?Standing instructions: role, rules, tone, format and what to refuse. It applies to the whole conversation and is the right place for policy.
44LLMWhat is a reasoning (thinking) model and when is it worth it?A model that works through a problem internally before answering. Worth it for multi-step maths, code and planning; wasteful for simple lookups and short answers.
45LLMWhat is effort (or reasoning budget) in modern model APIs?A setting that controls how much the model thinks and how thorough its answer is. Higher effort can improve hard tasks at the cost of latency and tokens.
46LLMWhat is a knowledge cut-off?The date after which the model has no training data. Anything newer must come from retrieval or tools.
47LLMWhat are open-weight models and why choose one?Models whose weights you can download and run yourself. Chosen for data control, offline use, customisation or cost at very high volume; you take on hosting and safety work.
48LLMWhat is fine-tuning good for, and what is it bad for?Good for style, format and narrow repeated tasks. Bad for adding fast-changing facts, which belong in retrieval.
49LLMWhat is multimodal input?A model that accepts images, audio or documents as well as text, such as reading a scanned invoice.
50PromptingWhat is few-shot prompting?Putting a few worked examples in the prompt so the model copies the pattern. Good for format and tone; costs tokens on every call.
51PromptingHow do you write a good prompt for a production task?State the role and goal, give context and data clearly separated (for example in tags), list rules and the output format, show an example, and say what to do when unsure. Then test it on a golden set.
52PromptingWhat is prompt chaining?Splitting a task into steps, each with its own prompt, and passing outputs forward. Easier to test and debug than one huge prompt.
53PromptingWhy separate instructions from data in a prompt?So text inside the data cannot be read as instructions, which reduces prompt injection and confusion.
54EmbeddingsHow are embeddings different from keyword search?Keyword search matches exact words; embeddings match meaning, so 'holiday' can find 'paid leave'. Keyword search is better for exact codes and names.
55EmbeddingsWhat is the dimension of an embedding?The length of the vector, often hundreds to a few thousand numbers. Higher dimensions can hold more nuance but cost more storage and search time.
56EmbeddingsCan you mix embeddings from two different models?No. Vectors from different models live in different spaces. Change model, re-embed everything.
57RAGWhat is hybrid search?Combining keyword (BM25) and vector search results, usually with a weighted merge. It finds both exact terms and paraphrases.
58RAGWhat is query rewriting?Using a model to turn a vague or conversational question into a clear search query, for example adding the subject from earlier in the chat.
59RAGWhat is top-k and how do you pick k?The number of chunks retrieved. Too small misses answers; too big adds noise and cost. Choose by measuring recall and answer quality on the golden set; 3 to 8 is common.
60RAGWhat is contextual retrieval?Adding a short description of where a chunk sits in its document before embedding it, so a chunk like 'It rose 3%' carries its subject.
61RAGHow do you keep a RAG index fresh?Re-index changed documents on a schedule or event, store document versions and dates, and remove superseded chunks.
62RAGHow do you enforce access control in RAG?Store access labels with each chunk and filter by the user's permissions at retrieval time, before anything reaches the model.
63RAGWhen is RAG the wrong choice?When answers need calculation over structured data (use SQL or tools), when the knowledge is tiny and stable (put it in the prompt), or when the task is style rather than facts (prompting or fine-tuning).
64ChunkingFixed-size or recursive chunking: which first?Recursive, because it respects paragraphs and sentences. Measure recall@k before trying anything fancier.
65ChunkingHow do you chunk tables?Keep each row with its header, or rewrite rows as sentences, so a chunk is meaningful on its own.
66Vector DBWhat is an approximate nearest neighbour index?A structure such as HNSW that finds near-best matches very fast by not comparing against every vector. You trade a little recall for a lot of speed.
67Vector DBWhat is metadata filtering?Restricting search to chunks whose metadata matches, such as country or department, before or during the vector search.
68Vector DBCan PostgreSQL be a vector database?Yes, with the pgvector extension. Good when you already run Postgres and need joins, filters and transactions alongside vectors.
69AgentsWorkflow or agent: how do you choose?Use a fixed workflow when the steps are known; use an agent only when the model must choose steps at run time. Workflows are cheaper and easier to test.
70AgentsWhat is the agent loop?The model decides an action, the code runs the tool, the result goes back to the model, and this repeats until the model answers or a limit is hit.
71AgentsWhat is a multi-agent system and its main risk?Several agents with different roles passing work between them. Main risks: cost, loops and errors compounding between agents; add limits and checks.
72AgentsWhat memory does an agent have?Short-term: the conversation and tool results in the context window. Long-term: notes or vectors stored outside and retrieved when needed.
73AgentsHow do you evaluate an agent?Score task success on a set of realistic tasks, plus steps taken, tool-call accuracy, cost and safety violations. Check the trajectory, not only the final answer.
74ToolsWhat makes a good tool definition?A clear name, a description of when to use it, a strict input schema with types and limits, and outputs that are short and structured.
75ToolsHow do you make tool use safe?Least privilege, validate inputs in code, treat outputs as data, require human approval for actions with real-world effects, and log every call.
76ToolsWhat happens if a tool fails?Return a clear error to the model as the tool result so it can try another way, and stop after a set number of failures.
77MCPMCP server versus client?The server exposes tools, resources and prompts (for example a ticket system); the client is the AI application that connects to it and offers them to the model.
78MCPWhat security risks does MCP add?Over-broad permissions, untrusted servers, and injected instructions in tool output. Approve servers, scope credentials and review actions.
79EvalsWhat is the difference between offline and online evaluation?Offline runs a fixed test set before release; online measures live traffic after release (feedback, escalations, sampled reviews). You need both.
80EvalsWhat metrics would you use for a RAG system?Retrieval recall@k, answer accuracy, citation accuracy, groundedness, correct refusal rate, latency p95 and cost per answer.
81EvalsHow big should a golden set be?Start with 30 to 50 real questions covering the main intents and edge cases; grow it with every failure found. Coverage matters more than size.
82EvalsHow do you check an LLM judge is reliable?Compare its scores with human labels on a sample, measure agreement, fix the rubric, and re-check whenever the judge model or prompt changes.
83EvalsWhat is regression testing for prompts?Running the full golden set after every prompt change so a fix for one case does not break others.
84HallucinationsWhat is the difference between faithfulness and correctness?Faithfulness means the answer matches the sources given; correctness means it matches the truth. A faithful answer from an outdated document is still wrong.
85HallucinationsHow do citations help?They tie each claim to a source users can check, and they let you measure whether the cited source supports the claim.
86SecurityWhat is data exfiltration through an agent?Injected instructions make an agent send private data out, for example through a URL or an email tool. Block outbound tools, or require approval, for untrusted contexts.
87SecurityHow should API keys be handled?Stored in a secret manager or environment variables, never in code, logs or the browser; rotated, scoped and monitored.
88SecurityWhat is jailbreaking?Prompts designed to make the model ignore its safety rules. Defend with the provider's safety features, input and output checks, and limited capabilities.
89LatencyWhat is time to first token and how do you improve it?The wait before output starts. Improve it with streaming, a shorter prompt, prompt caching and a faster model.
90LatencyHow does parallelism help?Independent steps, such as searching several sources, can run at the same time, so total time is the slowest step instead of the sum.
91CostWhat is prompt caching?The provider stores a repeated prompt prefix so later calls that reuse it are cheaper and faster. Put fixed content first and changing content last.
92CostWhat is the batch API used for?Non-urgent jobs such as nightly summaries or evals, sent together for a large discount with results returned later.
93CostWhat is model routing?Sending each request to the cheapest model that can handle it, for example a small model for classification and a large one for hard questions.
94LLMOpsWhat is a canary release for an AI feature?Releasing a new prompt or model to a small share of users first and comparing metrics before a full rollout.
95LLMOpsWhat is drift and how do you catch it?A change in user questions or data that lowers quality. Catch it by tracking topic mix, refusal and feedback rates and by sampling conversations weekly.
96LLMOpsWhy pin model versions?So behaviour does not change without your eval running first. Move to a new version deliberately, after testing.
97DeploymentWhy containerise an AI service?The same image runs the same everywhere, with fixed Python and library versions, which makes deploys and rollbacks reliable.
98DeploymentWhat does a health check endpoint do?Gives the platform a cheap way to confirm the service is up, so it can restart or stop routing traffic to an unhealthy instance.
99ArchitectureWhere should guardrails sit in the architecture?At every boundary: input, retrieval, before tools act, and output. No single layer is enough.
100Responsible AIWhat is bias in an AI system and how do you test for it?Systematically worse outcomes for some groups. Test by slicing eval results by language, region or user group and comparing.
101Responsible AIWhat should an AI feature disclose to users?That they are talking to AI, its limits, how to reach a human, and how their data is used.

AI product management

#AreaQuestionModel answer
1StrategyHow do you decide if a problem needs AI?Check whether it needs language or judgement that rules cannot handle, whether data exists, and whether a simpler solution works first.
2StrategyHow is AI PM different from traditional PM?Outputs vary, so quality must be defined, measured and monitored, and failure cases planned for.
3DiscoveryHow would you validate an AI feature idea before building?Interview users, run a manual or wizard-of-oz prototype, measure the task time and accuracy the user needs, then pilot.
4PrioritisationHow do you prioritise AI use cases?Score impact, effort, risk, data readiness and time to value; start with a high-value, low-risk workflow.
5MetricsWhat is a North Star metric for an AI support bot?Resolution rate with safe escalation: correct resolutions per week, which reflects both value and quality.
6MetricsWhich metrics would you track after launch?Task completion, escalation rate, accuracy sample, hallucination rate, cost per task, latency and satisfaction.
7Trade-offsBuild or buy?Compare time to value, three-year cost, data privacy, differentiation and the team's ability to maintain; pilot to decide.
8Trade-offsHow do you choose a model?Start with the cheapest model that passes the golden dataset; upgrade only where quality needs it, and check privacy terms.
9DataWhat data do you need for a RAG product?Documents with owners, permissions, freshness rules and a plan to remove stale content.
10EvaluationHow do you agree a quality bar with stakeholders?Define measurable thresholds per use case, the acceptable error rate, and the human review path for failures.
11Responsible AIHow would you handle a customer's personal data?Minimise what is sent, mask personal data in logs, apply retention rules, and get legal review.
12GovernanceWhat does AI governance include?Use policies, approval for new use cases, risk assessment, audit logs and clear accountability.
13StakeholdersHow do you manage an engineer who says the model cannot do it?Ask what evidence they have, run a small evaluation together, and agree on a test that would change the decision.
14Business caseHow do you calculate ROI for an AI assistant?Hours saved times loaded cost, plus revenue effects, minus build, run and evaluation costs over a set period.
15LaunchHow would you launch an AI feature safely?Limited beta, human approval for risky actions, monitoring, a rollback plan and clear user feedback loops.
16CaseA chatbot gives wrong refund policy answers. What do you do?Contain: restrict or switch off the topic; investigate the retrieved sources; fix the document or prompt; add the case to the golden dataset; monitor.
17StrategyWhat makes a good first AI use case for a company?High volume, clear success measure, low harm when wrong, available data and an owner who wants it. Internal tools often fit before customer-facing ones.
18StrategyHow do you write an AI product vision?Name the user, the job they struggle with, how AI changes it, and the measurable outcome in 12 to 24 months, plus what you will not do.
19StrategyWhat is a moat for an AI product when everyone uses the same models?Proprietary data and feedback loops, workflow integration, distribution, trust and evaluation know-how, not the model itself.
20DiscoveryHow do you find AI opportunities in a workflow?Map the workflow step by step, time each step, find language-heavy, repetitive or judgement steps, and check which have data and tolerate some error.
21DiscoveryWhat is a Wizard of Oz test?Humans pretend to be the AI behind a real interface to test demand and the experience before building the model part.
22DiscoveryHow do you test whether users trust AI output?Watch them use it: do they check sources, edit, or ignore it? Track acceptance and edit rates, and ask what would make them rely on it.
23PrioritisationHow do you size the value of an AI feature?Volume x time saved per task x loaded cost x expected adoption, plus revenue or risk effects, minus build and run costs.
24PrioritisationHow do you say no to an AI feature request?Show the evidence: the problem is rare, a simpler fix exists, the data is missing or the risk is too high. Offer the smaller step you will take instead.
25MetricsWhat is the difference between model metrics and product metrics?Model metrics measure output quality (accuracy, groundedness); product metrics measure user and business results (adoption, time saved, resolution). Good model scores do not guarantee product success.
26MetricsName guardrail metrics for an AI feature.Harmful or wrong answer rate, escalation rate, complaint rate, cost per task and latency p95. They must not get worse while the main metric improves.
27MetricsHow do you measure time saved?Time the task with and without the feature on matched samples, or log task durations before and after, and check quality is the same.
28MetricsWhat does a good AI dashboard show?Volume, quality (eval score and sampled reviews), user feedback, escalation, latency, cost, and splits by version, topic and segment.
29Trade-offsAccuracy versus coverage: how do you decide?Decide by the cost of a wrong answer. High-risk domains answer fewer questions with higher accuracy and refuse more; low-risk ones can answer more.
30Trade-offsLarge model or small model?Start with the strongest model to prove value, build the eval, then test smaller or cheaper options against the same bar.
31Trade-offsPrompting, RAG or fine-tuning?Prompting first; RAG when answers depend on your own or changing knowledge; fine-tuning for consistent style or narrow tasks at scale.
32DataWhat makes documents ready for RAG?A clear owner, current versions, no duplicates, readable text (not scans without OCR), access labels and a refresh process.
33DataHow do you get labelled data for evaluation?Collect real questions from logs or tickets, have experts write expected answers and sources, and add failures from production every week.
34EvaluationWho should own the golden set?The PM owns what good looks like with domain experts; engineers own the harness. Changes to expected answers need review.
35EvaluationWhat is a release bar?The minimum scores a version must meet to ship, agreed in advance, for example 90 percent accuracy and 100 percent correct refusal on unsafe questions.
36Responsible AIHow would you handle a biased output reported by a user?Acknowledge, reproduce, assess impact, contain if needed, fix the data or prompt, add the case to the eval and report the change.
37Responsible AIWhen must a human stay in the loop?When an error is costly or irreversible: money, health, legal, hiring or account changes. The AI can draft; a person decides.
38GovernanceWhat goes into an AI risk register?Each risk (hallucination, data leak, injection, bias, cost overrun, outage), likelihood, impact, owner, mitigation and how it is monitored.
39GovernanceHow do privacy rules such as India's DPDP Act affect an AI product?You need a lawful basis or consent for personal data, purpose limits, minimisation, security, retention limits and a way to handle user requests. Check with legal for specifics.
40StakeholdersHow do you explain AI uncertainty to executives?Use numbers from the eval (for example 92 of 100 answers correct), show examples of the failures, and explain the safeguards and the plan to improve.
41StakeholdersLegal wants to block the launch. What do you do?Understand the specific risk, show the controls and eval evidence, propose a narrower or staged launch, and agree the conditions to expand.
42Business caseHow do you price an AI feature?Base it on value delivered and on cost to serve: include tokens per task at expected usage, set limits or tiers for heavy users, and watch margin.
43Business caseWhat hidden costs do AI products have?Evaluation and labelling, monitoring, human review, prompt maintenance, provider price changes, retries and support for wrong answers.
44LaunchWhat is in an AI launch checklist?Eval above the bar, red-team results, monitoring and alerts, rollback switch, human handoff, user disclosure, support briefed, and a staged rollout plan.
45LaunchHow do you run an A/B test for an AI feature?Randomise users, pick a primary metric and guardrails up front, run long enough for the novelty effect to fade, and check results by segment.
46CaseAdoption of your AI assistant is 10 percent after a month. What do you do?Find out why: discoverability, trust, quality or fit with the workflow. Look at usage funnels and talk to non-users, then fix the biggest blocker first.
47CaseCosts doubled last month. What do you do?Break cost down by feature, prompt version and user; look for longer prompts, retries, heavy users or a model change; apply caching, limits or routing; re-run the eval.
48CaseA competitor launches an AI feature. Should you copy it?Only if it solves a real problem for your users better than your current plan. Check the evidence and your data advantage, then decide.
49CaseDesign a metric framework for an AI meeting summariser.North Star: meetings with summaries used. Quality: rep edit rate, missed action items. Product: weekly active users. Business: time saved and CRM data completeness. Guardrails: privacy incidents, latency.
50CaseYour AI tutor gives a wrong maths answer to a student. Walk through your response.Contain (add a check or disable the topic), investigate the cause, fix, add the case to the eval, communicate with the student and teachers, and track the rate going forward.
Practice

Subject interview questions with pointers

Subject 1: Python for AI beginners

Q: What is a virtual environment and why use one?
An isolated folder of libraries for one project, so versions of packages do not conflict between projects.

Subject 2: APIs and backend fundamentals

Q: What does a 429 status code mean?
Too many requests: the client has exceeded a rate limit and should wait and retry, usually with exponential backoff.

Subject 3: LLM and generative AI fundamentals

Q: What is a token?
A piece of text (a word, part of a word or punctuation) that the model reads and produces. Usage and cost are measured in tokens.

Q: What is temperature?
A setting that controls randomness in sampling: lower values give more predictable output.

Subject 4: LLM API integration: your first AI application

Q: What is the difference between a system message and a user message?
The system message sets the model's role and rules; the user message is the request for this turn.

Subject 5: Understanding RAG (retrieval-augmented generation)

Q: When would you choose RAG instead of fine-tuning?
When knowledge changes often, must be cited, or is large. Fine-tuning changes behaviour and style better than it stores facts.

Q: Why do chunks overlap?
So information that sits across a chunk boundary is still fully contained in at least one chunk.

Subject 6: Document processing and chunking

Q: What is chunk overlap?
Repeating some text between neighbouring chunks so answers that span a boundary are not split.

Subject 7: Embeddings and vector databases

Q: What is cosine similarity?
A measure of the angle between two vectors. Values near 1 mean very similar meaning in embedding space.

Q: What is hybrid search?
Combining keyword (lexical) search with vector (semantic) search, then merging the results.

Subject 8: Project: PDF-based RAG chatbot

Q: How do you stop a RAG bot making things up?
Ground answers in retrieved text, instruct it to cite and to refuse when context is missing, and evaluate refusals as well as answers.

Subject 9: AI agent fundamentals

Q: What is the difference between a chatbot and an agent?
A chatbot answers in one turn; an agent plans and uses tools over several steps until the goal is met.

Subject 10: Tool calling and agent development

Q: How do you make tool calling safe?
Least-privilege tools, input validation, approvals for writes, logging every call and a step limit.

Subject 11: Model Context Protocol (MCP)

Q: What problem does MCP solve?
It standardises how AI applications discover and use external tools and data, so each integration is built once instead of once per app.

Subject 12: Project: AI research agent

Q: How would you evaluate a research agent?
Check claim accuracy against sources, source coverage, conflict detection and time saved per report.

Subject 13: AI evaluation

Q: What is a golden dataset?
A fixed, expert-approved set of inputs with expected answers or checkable facts, used to test every change.

Q: What is faithfulness?
Whether each claim in the answer is supported by the retrieved context.

Subject 14: Hallucinations, guardrails and AI quality

Q: How do you reduce hallucinations in production?
Ground answers in retrieved sources, require citations, refuse when unsupported, evaluate regularly and route risky answers to humans.

Subject 15: Latency and cost

Q: What is time to first token?
The delay before the first token of the answer appears. It drives perceived speed in chat products.

Subject 16: LLMOps: running AI in production

Q: What do you log for an LLM request?
Prompt version, model version, retrieved sources, input and output tokens, latency, errors and user feedback, with personal data removed.

Subject 17: AI product discovery

Q: How do you decide whether a problem needs AI?
Check whether the task needs language or judgement that rules cannot handle, whether the data exists, and whether a simpler solution meets the need first.

Subject 18: End-to-end AI project: enterprise knowledge and research copilot

Q: How would you scope an AI product for the first release?
Pick the smallest workflow that delivers measurable value, define the quality bar, and defer features that do not test a key assumption.

Subject 19: AI product documentation

Q: What belongs in an AI PRD that a normal PRD does not need?
Quality thresholds and evaluation method, data sources and their permissions, human-in-the-loop points, and failure handling.

Subject 20: Deployment, GitHub and portfolio

Q: How do you keep API keys out of your code?
Store them in environment variables or a secret manager, add the env file to .gitignore, and rotate any key that was ever committed.

Subject 21: AI product management fundamentals

Q: How is AI product management different from traditional product management?
Outputs are probabilistic, so the PM must define and monitor quality thresholds, plan for failure cases, and manage data and governance risk.

Subject 22: AI product metrics

Q: What is a North Star metric for an AI support assistant?
Resolution rate with a safe escalation rate: the share of customer issues solved correctly without harm, which captures both value and quality.

Subject 23: AI system design

Q: Design a customer support AI assistant for a bank.
Clarify scope and risk; retrieve from approved policy and product documents; use tools with approval for account changes; log everything; measure resolution and escalation; add a human handoff.

Subject 24: Technical interview preparation

Q: Explain RAG to a business executive in one minute.
The model answers questions by first looking up the relevant pages from our own documents, then writing an answer with citations, so it stays accurate and up to date.

Subject 25: AI product management interview preparation

Q: How would you decide whether to build or buy an AI capability?
Compare time to value, cost over three years, data privacy, differentiation and the team's ability to maintain it, then pilot with a measurable test.

Subject 26: Mock interviews (three rounds)

Q: Tell me about an AI project you built.
Use the capstone: the problem, the users, one important decision with its trade-off, the evaluation result, and what you would do next.
