UX Fundamentals :: UX covers the whole experience: usefulness, usability, findability, credibility and delight. A feature can be useful but hard to find, so the PM must consider each aspect. Start evaluation with whether the user can complete the core task.
UI Fundamentals :: UI is the visual layer: layout, typography, colour, components and states such as hover and error. Consistent components reduce cognitive load. A design system keeps UI consistent across screens and teams.
Human-Centred Design :: Human-centred design involves users throughout the process, from research to testing. It starts from user needs and checks solutions with real people. PMs contribute by bringing research findings into design discussions early.
Design Thinking Process :: The process of empathise, define, ideate, prototype and test is applied repeatedly to product problems. Each loop should narrow uncertainty. Stop when the riskiest assumptions are tested, not when the design looks finished.
Information Architecture :: Information architecture organises and labels content and navigation so users can find things. Good labels use the words users use, not internal jargon. Test labels with card sorting or tree tests before building menus.
User Flows :: A user flow diagrams the steps a user takes to complete a task, including decisions and error paths. Flows expose missing states, such as what happens when a payment fails. Review flows with engineers to catch dependencies early.
Wireframing :: Wireframes are low-detail layouts that settle structure and content before visual design. They keep discussion on function. Use boxes and labels, not colours and icons, so feedback focuses on the structure.
Low-Fidelity and High-Fidelity Prototypes :: Low-fidelity prototypes (paper or simple boxes) test ideas quickly and cheaply. High-fidelity prototypes look and behave like the final product, and are better for testing realistic tasks. Match the fidelity to the question you need answered.
Interactive Prototyping :: Interactive prototypes simulate flows so users can click through a task before engineering starts. Test the riskiest task first, for example a checkout step, and watch where users hesitate.
Figma Fundamentals :: Figma is the common design tool. Learn frames, components, auto layout, variables and prototyping. Components keep designs consistent, and variables let you change colours or spacing in one place.
Usability Testing :: Usability testing watches representative users attempt tasks. Five users per round typically reveal most major usability issues. Record the task, the wrong turns and the words users use, then fix the most severe issues first.
Design Validation :: Design validation confirms that a design solves the problem using test results, metrics and feedback. Before scaling a design, define what success looks like, such as task completion above 80% without help.
Accessibility and Inclusive Design :: Inclusive design serves people with different abilities and contexts. WCAG guidelines define contrast, keyboard access, screen reader support and clear language. Accessibility improves the product for everyone, not only for disabled users.
Mobile-First Product Design :: Designing for the smallest screen first forces focus on essential content and actions. Then expand to larger screens. Many users in India access services mainly on low-end phones and slow networks, so design for those constraints first.
Conversational UX :: Conversational design covers turn-taking, clarifying questions, tone, error recovery and hand-off to a human. A good assistant states its scope clearly and recovers gracefully when it misunderstands the user.
AI-First User Experience :: AI-first design starts from what the AI does well and designs fallbacks for what it cannot do. It makes uncertainty, sources and user control visible so people can judge when to rely on the output.
Human-AI Interaction Design :: These patterns set expectations, show confidence levels, let users correct the AI and keep them in control. Example: an AI draft is shown with editable fields and an undo option, not auto-sent.
