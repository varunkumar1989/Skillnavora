Data Fundamentals for Product Managers :: Data types include numbers, categories, timestamps and text. Events record what a user did, while tables store entities such as accounts. Before analysing anything, ask what decision the data should inform.
Descriptive Statistics :: Mean, median, mode, spread and percentiles summarise data. Use medians and percentiles for skewed measures such as session length, because a few very long sessions distort the mean.
Probability Fundamentals :: Probability measures how likely an outcome is. Conditional probability asks how likely an outcome is given another event, such as churn given a failed payment. Distributions describe the range of possible values for a metric.
Hypothesis Testing :: Hypothesis testing asks whether an observed difference is likely due to chance. The null hypothesis states there is no difference. A p-value below a pre-set threshold, often 0.05, suggests the difference is unlikely to be chance, but it does not measure business importance.
SQL Fundamentals :: SELECT, WHERE, GROUP BY, ORDER BY and LIMIT let you query tables. Example: SELECT city, COUNT(*) FROM orders WHERE status = 'paid' GROUP BY city returns paid orders per city.
SQL Joins and Aggregations :: Joins combine tables on keys. Inner joins keep matches only; left joins keep all rows from the left table. Aggregations such as COUNT, SUM and AVG summarise groups. Check row counts after each join to avoid double counting.
Advanced SQL for Product Analytics :: Window functions, common table expressions and date functions answer product questions such as "what share of users returned on day 7?" Build cohort tables step by step and check each intermediate result.
Excel and Google Sheets :: Pivot tables, lookups, formulas and charts are fast tools for analysis and sharing. Use them for quick exploration and small datasets. Move to SQL and a BI tool when data grows or needs refreshing.
Data Visualisation :: Choose charts that make the comparison obvious: bars for categories, lines for trends. Label axes clearly, start bars at zero and avoid decorative effects that distort the message.
Tableau and Power BI :: These BI tools build interactive dashboards and self-serve reports on warehouse data. Good dashboards show a small set of decisions and the metric definitions beside them, so people interpret the numbers the same way.
Product Analytics Fundamentals :: Product analytics records user behaviour as events with properties, then analyses funnels, cohorts and paths. Clean event names and a tracking plan prevent confusing results later.
Funnel Analysis :: A funnel measures conversion between steps, such as visit, signup, activation and purchase. The biggest drop is a starting point for investigation, not an answer. Segment the funnel by source and device to see who drops off.
Cohort Analysis :: A cohort groups users by a shared start, such as signup week. Following each cohort shows whether newer users behave better or worse than older ones over time.
Retention Analysis :: Retention shows how many users return over days or weeks. A retention curve that flattens at a healthy level is a common sign of product-market fit, while a curve that keeps falling signals a problem.
Churn Analysis :: Churn analysis asks why and when customers leave, using exit surveys, usage before cancellation and segment comparisons. Churn usually follows a clear drop in usage, so track engagement as an early warning.
Conversion Rate Optimisation :: CRO improves the share of visitors who complete a goal through research, testing and friction removal. Start with the steps where users stall, then test changes against a clear hypothesis.
Customer Segmentation :: Segments group users by behaviour, value or need. A segment is useful when it suggests a different product choice or message. Segments based only on demographics often fail to change any decision.
A/B Testing :: An A/B test randomly splits users between two versions and compares a pre-chosen metric. Randomisation makes the difference causal. Decide the sample size and duration before starting, and do not stop early because one result looks good.
Multivariate Testing :: Multivariate tests vary several elements at once to find the best combination. They need far more traffic than A/B tests. Use them only when you have enough users and a clear reason to test interactions.
Experimentation Frameworks :: A framework sets a repeatable process: hypothesis, primary metric, guardrails, sample size, run length, analysis and decision rule. Teams that follow one framework make fewer false conclusions.
Event Tracking :: Event tracking defines and logs user actions with a consistent naming plan, for example "checkout_started" with properties. Review the plan when features change so historical data remains comparable.
Product Analytics Dashboards :: A dashboard shows key metrics for the team, with a clear owner, definitions and thresholds that trigger action. A dashboard without an owner tends to be ignored within months.
Mixpanel :: Mixpanel is event-based analytics for funnels, retention and cohorts. It suits teams that want quick self-serve analysis of user behaviour in web and mobile products.
Amplitude :: Amplitude offers behavioural cohorts, user journeys and experimentation tools. Like Mixpanel, it works from events, so the quality of the tracking plan determines the quality of the analysis.
Google Analytics :: Google Analytics measures web and app traffic, acquisition channels and conversions. It is a common starting point for marketing data. Its event model and reports differ from product analytics tools, so check definitions before comparing numbers.
Data-Driven Product Decisions :: Combine quantitative data with qualitative insight. Write the decision rule before looking at results, for example "we will launch if activation rises by at least 3 points without lowering revenue per user". This prevents rationalising the result afterward.
