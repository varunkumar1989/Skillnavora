## How it works
MiroFish reads what you plan to launch, builds a small world of AI people with different backgrounds, lets them react and talk to each other, and reports where opinions land. It's a cheap rehearsal before real customers see it.

```figure mirofish-flow
```

## What you need
- A Mac or Windows computer.
- Node.js 18 or newer.
- Python 3.11 or 3.12.
- **uv**, the Python package manager.
- An AI API key. The project suggests Alibaba's Qwen-plus through DashScope, but any OpenAI-compatible API works.
- A Zep Cloud key, which gives the AI personas memory. The free monthly tier is enough to start.

## Step 1: Download the code
```cmd Clone the repository
git clone https://github.com/666ghj/MiroFish.git
cd MiroFish
```

## Step 2: Get your two keys
- **AI key:** create an account with a provider and copy three things: the API key, its base URL and the model name. The default is Alibaba Bailian / DashScope with `qwen-plus`; OpenAI, or Gemini through a compatible proxy, also work.
- **Zep Cloud key:** sign up free at getzep.com and copy the API key. The free monthly quota covers light use.

## Step 3: Fill in the settings file
Copy the example file:

```cmd Copy the settings file
cp .env.example .env
```

Open `.env` and add your values, one per line:

```cmd Your .env values
LLM_API_KEY=your_api_key
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL_NAME=qwen-plus
ZEP_API_KEY=your_zep_api_key
```

> Using another provider? Change `LLM_BASE_URL` and `LLM_MODEL_NAME` to that provider's values.

> Want it free? Point `LLM_BASE_URL` at your own FreeLLMAPI server (see the FreeLLMAPI guide in this library), which routes to free AI tiers through one OpenAI-compatible address.

## Step 4: Install everything
One command installs the root project, the frontend and the backend:

```cmd Install everything
npm run setup:all
```

Or install in stages:

```cmd Install in stages
npm run setup
npm run setup:backend
```

## Step 5: Start MiroFish
```cmd Start MiroFish
npm run dev
```

Then open:
- Dashboard (frontend): `http://localhost:3000`
- Backend API: `http://localhost:5001`

> Run them separately with `npm run backend` and `npm run frontend`. With Docker, run `docker compose up -d` after Step 3 for the same ports.

> Fully local and free (no cloud AI bill): the community fork **MiroFish-Offline** swaps in Neo4j and Ollama. It needs a powerful computer, and local models are weaker than the big cloud models.

## Step 6: Run your first simulation
1. **Upload your material:** the launch post, landing-page text, new price, ad creative or a short product description. Research documents and background notes also work.
2. **Describe what you want to learn**, in plain words. Example: "I'm launching a $49/month SaaS for indie founders. Test how they react to the price and the main headline. I worry it feels too expensive and too generic."
3. **Keep it small at first:** a modest number of agents and under about 40 rounds, to control cost while you learn.
4. **Run it.** MiroFish builds a knowledge graph from your material, creates AI personas with different backgrounds, lets them react and talk to each other, and tracks how opinions change.

> Use a cheaper, faster model while experimenting and save the best model for final runs. Watch your provider's usage page during the first few runs.

## Step 7: Read the report and ask follow-ups
You get two things:
- **A prediction report:** overall sentiment, the main objections, what worked and what fell flat.
- **A world you can explore:** chat with any persona ("why did the price put you off?") and ask the Report Agent follow-up questions.

Fix the objections and framing problems it finds, then run again to compare.

## Step 8: Know the limits
- **Simulated is not real.** Treat results as ideas to test, not facts.
- **Quality in, quality out.** Personas are only as good as your material and your question.
- **Realism costs money.** Thousands of simulated customers are possible but expensive; most value comes from small, well-framed runs.

## Extra from Vaitis
- **Confirm with real people:** after the simulation, run a quick poll or a landing-page test with real visitors before you change your price.
- **Good questions to ask the crowd:** "Which headline is clearer, A or B?", "What would stop you buying today?", "What price feels fair, and why?"
- **Save each run:** keep the report and the exact input text, so you can compare versions over time.
