## What you need
- A Mac or Windows computer with Claude Code installed (see the Harvey guide, Step 1).
- An **OmniDimension** account for the AI voice agent, plus a phone number (buy one inside OmniDimension).
- A **Vercel** account to put the site online.
- A **Supabase** account to store bookings and call data.
- A **Resend** account (or another email service) to email you the recording and details.
- 30 to 45 minutes for a first version.

!> Most steps are simple. The hard part is Step 3: the booking must start the call, and the call must report back. That is what turns a nice website into a working system, so go slowly there.

## Step 1: Build the website
Open Claude Code in an empty folder and send:

```prompt Build the site
Build a hospital appointment booking website with Next.js and Tailwind. Pages: Home, Doctors, Book Appointment, Contact. The booking form collects patient name, phone number, doctor, date, time and reason for visit. Style: clean, calm and medical, white with soft blue, modern and mobile-first. Keep it as one project I can deploy to Vercel.
```

Open the preview and keep asking for changes until it looks right:

```prompt Refine the design
Make the hero section simpler with a bigger heading. Move the booking button to the top. Give the form rounded corners.
```

Then add your real details so it no longer looks like a demo:

```prompt Add your real content
Replace all placeholder content with my real hospital.
Doctors: [name and specialty for each]
Services: [list]
Timings: [list]
Contact: [phone, email, address]
Use the logo and photos I have added to the project folder.
```

> Put your logo and photos in the project folder first, then tell Claude the file names.

## Step 2: Create the AI voice agent
In OmniDimension, create a new **Voice AI assistant**. Choose a warm, natural voice and give it these instructions (change the hospital name):

```prompt Voice agent instructions
You are the front-desk receptionist at [Hospital Name]. You are calling a patient to confirm the appointment they just booked. Be warm, clear and brief.
1. Greet the patient by name.
2. Confirm the doctor, date and time.
3. Ask whether the time still suits them.
4. If yes, confirm and thank them.
5. If no, say you will note a reschedule request and someone will call back.
Keep the call under one minute. Never give medical advice.
```

Then:
- Buy a phone number in OmniDimension (or import a Twilio number) and attach it to this agent. This number calls patients.
- Copy your **API key** and **Agent ID**. You need both in Step 3.

> Make a test call to your own phone before connecting anything. Fix the voice and script now, not later.

## Step 3: Connect the booking to the call and go live
Back in Claude Code, send (add your Agent ID):

```prompt Connect the booking
When someone submits the booking form, do three things on the server:
1. Save the booking to Supabase.
2. Call the OmniDimension API to start a confirmation call to the patient's phone, using Agent ID [your agent id].
3. Email me the booking details.
Read these from environment variables and never hard-code them: OMNIDIM_API_KEY, OMNIDIM_AGENT_ID, SUPABASE_URL, SUPABASE_ANON_KEY, RESEND_API_KEY, MY_EMAIL. Show me the .env file I need to fill in.
```

Deploy it. Add the Vercel plugin in Claude Code, then send:

```prompt Deploy to Vercel
Add Vercel. Deploy this project to my Vercel account and give me the live link.
```

In Vercel, go to **Project → Settings → Environment Variables**, add your `.env` values and redeploy.

Close the loop: in OmniDimension, add a **webhook** that fires after each call and points to your live site, for example `https://yoursite.com/api/call-result`. Then in Claude Code:

```prompt Receive the call result
Add an API route at /api/call-result that receives OmniDimension's webhook after each call. Save the recording link, transcript and outcome in Supabase against the matching booking, and email me the recording link with the patient details.
```

Now the loop runs on its own: a patient books, the AI calls within about a minute, and the result and recording reach Supabase and your inbox.

## Step 4: Set up Supabase and your dashboard
Create a free Supabase project. In the **SQL editor**, create two tables:

```sql Create the tables
create table bookings (
  id uuid primary key default gen_random_uuid(),
  name text,
  phone text,
  doctor text,
  appointment_date date,
  appointment_time text,
  reason text,
  status text default 'pending',
  created_at timestamptz default now()
);

create table call_logs (
  id uuid primary key default gen_random_uuid(),
  booking_id uuid references bookings(id),
  recording_url text,
  transcript text,
  outcome text,
  created_at timestamptz default now()
);
```

Copy the **Project URL** and **anon key** from **Settings → API** into your environment variables (same names as Step 3). Then add an admin page:

```prompt Build the admin page
Add a password-protected admin page at /admin. Show a table of all bookings with their status and, for each, the linked call recording and outcome. Let me change a booking's status from this page.
```

Bookings, recordings and statuses now live in one place you can edit.

## Step 5: Test before going live
Book a test appointment with your own number and check the whole loop: the call, the email and the dashboard.

!> Calls cost money: you pay for the phone number and every minute. Start small and watch usage.

!> Only call people who gave their number to book. Confirming their own appointment is fine; never use this to cold-call strangers.

## Extra from Vaitis
- **Patient data is sensitive.** Turn on Row Level Security in Supabase, keep the admin page behind a strong password, and store only what you need. Follow your country's health-data rules (in India, the DPDP Act).
- **Reminders:** ask Claude to add an SMS or WhatsApp reminder 24 hours before each appointment.
- **Same pattern, other businesses:** salons, clinics, coaching centres and car service centres can use the same "book, then AI calls to confirm" flow.
