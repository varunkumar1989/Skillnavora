## What you need
- Claude Code installed and working (see the Harvey guide, Step 1).
- A folder of songs you own or have permission to use (mp3 or similar).
- A few background images for the tracks.
- A rough idea of the look you want: colours, mood and layout.

!> Use only music and images you have the rights to. If the site goes public, other people's songs or artwork can get it taken down.

## Step 1: Describe the whole site in one prompt
Give Claude one clear, detailed prompt and let it build everything: structure, design, search and audio player. More detail now means fewer fixes later. A strong prompt covers:
- **What it is:** "a smaller music streaming site like Spotify".
- **Main sections:** home, search and a now-playing bar.
- **Player behaviour:** play, pause, skip, progress bar and duration.
- **Look:** dark theme, colours, font style.
- **Anything special:** for example, songs grouped by place or mood.

```prompt Example build prompt
Build a music streaming website like a smaller Spotify. Sections: a home page with playlists, a search page that filters songs as I type, and a now-playing bar fixed at the bottom. The player has play, pause, next, previous, a draggable progress bar and the track duration, and keeps playing while I move between pages. Dark theme with a green accent, rounded cards and a clean modern font. Group songs into playlists by mood. Use the songs and images in the /music and /images folders.
```

> Describe **behaviour**, not code. "The music keeps playing while I browse other pages" works better than naming a technical approach.

## Step 2: Add your songs and images
Put your songs and images into the project, then send one instruction:

```prompt Organise the media
Organise these songs and images and connect them to the player. Rename every file to a clean, consistent format, match each track with its background image, and read each song's real duration so the player shows the correct times.
```

Claude does the dull work: renaming files consistently, pairing each track with an image and reading real durations. You never label anything by hand.

## Step 3: Show Claude the bug instead of describing it
When something breaks, don't try to explain it in words. **Record your screen** while using the broken part, then upload the recording to Claude. This works better because:
- Claude sees the real behaviour: a broken layout, a missing image, a player that won't start.
- You don't have to guess what the problem is called.
- Claude can spot the cause and fix it directly.

> In the recording, do exactly the action that fails (click the button, load the page, press play) so the failure is on screen.

## Step 4: Finish and publish
Ask Claude to finish the project:

```prompt Finalise for hosting
Finalise the project for hosting: compress the images and audio so the site loads fast, delete unused files, and prepare everything for upload. Then give me step-by-step instructions to put it online for free, including which files to upload, where, and in what order.
```

Claude optimises the files, cleans the folder and prepares the build, then gives you exact publishing steps.

> The real lesson isn't the website: it's treating Claude like a developer who builds, tests, debugs and ships from start to finish.

## Extra from Vaitis
- **Free hosting options:** Cloudflare Pages, Netlify and Vercel all host a static site like this for free.
- **Large audio files:** many free hosts limit file size (Cloudflare Pages allows 25 MB per file). Ask Claude to convert songs to 128 to 192 kbps MP3 to stay under limits.
- **Next upgrades:** liked songs saved in the browser, a shuffle button, and keyboard shortcuts (space to play or pause).
