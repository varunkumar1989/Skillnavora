1. AI Video Creator and Editor

Lesson 1.1

Image-to-video and text-to-video platforms

  • Text-to-video vs image-to-video. Text-to-video builds a clip from a prompt.
  • Runway ML. A full creative suite with video generation, editing tools and camera controls.
  • Kling AI. A video generator known for strong motion and realism; it uses a credit system.
  • Pika Labs. Short clips and effects; quick for stylised results.
  • HeyGen. Talking avatars and translated video with lip-sync; useful for explainers and training.
  • Before you start. Plans, credits and features change often.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 30

Read more (official sites): Runway ↗ · Kling AI ↗ · Pika ↗ · HeyGen ↗

Lesson 1.2

Prompt engineering for consistent scenes and characters

  • The consistency formula. [Subject description] + [Style and lighting] + [Camera lens specs] + [Seed number or reference image].
  • Reference images. Most tools let you upload a reference of the character.
  • Seeds. Some tools expose a seed number; reusing it with similar prompts gives similar results.
  • Keep a character sheet. Write one fixed paragraph describing the character and paste it into every prompt.
  • Aspect ratio. The flag --ar 16:9 is Midjourney syntax.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 31

Read more (official sites): Runway learn ↗ · Midjourney docs ↗

Lesson 1.3

Video production case studies and prompts

  • How to use these. Treat each prompt as a starting point.
  • Respect. The mythological prompt depicts a religious figure.
  • Case study A: cartoon animation. 3D Pixar-style animation of a brave young explorer holding a glowing map inside an ancient temple, soft cinematic lighting, 8k resolution, highly detailed character desig
  • Case study B: epic mythological scene (Ramayan theme). Cinematic shot of Lord Rama standing on an ocean cliff holding a glowing bow, dramatic stormy sky, golden armour detailing, photorealistic render, wide-angle lens, Unreal
  • Case study C: dynamic action scene. Action camera tracking shot of a martial arts duel on a rainy neon-lit roof at night, slow-motion impact shot, wet reflections, cinematic motion blur, 80mm lens, anamorph
  • Case study D: multi-character narrative. Wide cinematic shot in a grand stone throne room: a regal King in velvet robes sitting beside a graceful Queen, while a shadowed figure in a dark hooded cloak approaches

Read this lesson with its practice task (PDF) · in the full lesson guide, page 32

Read more (official sites): Runway ↗ · Kling AI ↗

Lesson 1.4

Credit optimisation and efficiency

  • Two-stage method. Create the base image in an image tool (Midjourney or Leonardo.ai), approve it, then animate only the approved image in Runway or Kling.
  • Short test clips. Generate 3 to 5 second tests before a longer clip.
  • Reuse. Animate several shots from one approved set of images.
  • Track. Keep a sheet of credits spent per scene.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 33

Read more (official sites): Leonardo.ai ↗ · Midjourney ↗

Lesson 1.5

Post-production and audio sync

  • Voice-over. ElevenLabs creates voices from text.
  • Lip-sync. Match mouth movement to the audio in the video tool's lip-sync feature or in HeyGen.
  • Subtitles. CapCut can auto-generate subtitles; always proofread them.
  • Score and mix. Descript edits audio like text and helps arrange music; keep voice louder than music.

2. AI Integration Developer

Lesson 2.1

OpenAI API and Anthropic SDK integration in Node.js and Python

  • The call. Send messages (a system message and the user's message) to the model API and read the reply.
  • API keys. Keep keys in environment variables on the server, never in front-end code or the repository.
  • Handling errors. Expect rate limits and timeouts; retry with a short wait and give the user a clear message.
  • Costs. You pay for input and output tokens; set limits and log usage.
  • Model names. Names change; read the provider's current model list rather than copying an old name.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 34

Read more (official sites): Anthropic documentation ↗ · OpenAI documentation ↗

Lesson 2.2

Vector databases: Pinecone, ChromaDB and Weaviate

  • Embeddings. An embedding turns text into a list of numbers so similar meanings are near each other.
  • Similarity search. Find the stored items closest to the question's embedding, often by cosine similarity (the code below shows the idea with tiny vectors).
  • Choosing. ChromaDB is simple to run locally.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 35

Read more (official sites): Pinecone ↗ · Chroma ↗ · Weaviate ↗

Lesson 2.3

Retrieval-augmented generation (RAG) and document indexing

  • The pipeline. Split documents into chunks, embed and index them, retrieve the best chunks for a question, give them to the model with the question, and ask it to answer only from them
  • Chunking. Chunks of a few hundred words with a little overlap keep ideas together.
  • Failure modes. Wrong chunk retrieved, answer not in the documents, or the model ignoring the context.
  • Privacy. Index only documents you may use and respect who can see what.

3. Chatbot Developer

Lesson 3.1

RAG-powered bots in Voiceflow, Botpress and Flowise

  • Voiceflow. Visual conversation design with a knowledge base.
  • Botpress. A builder with knowledge bases, flows and channel connections.
  • Flowise. An open-source drag-and-drop builder for language-model flows, which can be self-hosted.
  • Design rules. Greet, state what the bot can do, answer from the knowledge base, offer a human, log unanswered questions and review them weekly.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 38

Lesson 3.2

WhatsApp Business API integration via Twilio and Wati

  • Consent. Message only people who opted in, and follow WhatsApp's business and commerce policies.
  • Templates. Business-started conversations use pre-approved templates; replies within the service window can be free-form.
  • Setup. Get a business account and phone number through the provider, set a webhook for incoming messages, and send replies through the API.
  • Providers. Twilio gives developer APIs; Wati is a no-code platform.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 38

4. Machine Learning and AI Engineer

Lesson 4.1

Data preprocessing and model training (Pandas, NumPy, Scikit-Learn, PyTorch)

  • Preprocessing. Clean missing values, fix types, encode categories and scale numbers where the model needs it.
  • Train and test split. Train on one part of the data and measure on rows the model has not seen.
  • Scikit-Learn. Classical models with a common fit and predict pattern.
  • PyTorch. Flexible framework for neural networks; use it when classical models are not enough.
  • Honest evaluation. One accuracy number on a tiny sample proves little.

6. n8n Expert

Lesson 6.1

Self-hosting n8n with Docker on DigitalOcean or AWS

  • Why self-host. More control and no per-run limits on the open-source edition, in exchange for maintaining the server.
  • Steps. Create a small server, install Docker, run the n8n image with a persistent volume, put it behind HTTPS with a reverse proxy, set a strong encryption key and sign-in, and
  • Security. Do not expose the editor without authentication; keep the server updated.

Lesson 6.2

Custom JavaScript nodes, error workflows and API polling

  • Code node. Run JavaScript on items to reshape data.
  • Error workflows. A separate workflow that runs when another fails and alerts you with the workflow name and the error.
  • Polling. Call an API on a schedule; remember the last item processed to avoid duplicates, and respect rate limits.

7. Vibe Coder

Lesson 7.1

AI-first coding workflows with Cursor, Replit Agent and Claude

  • Workflow. Describe the feature, let the assistant plan, build in small steps, run and read the output, then review the diff before accepting.
  • Prompt structure. Role, task, constraints, files involved and how to test.
  • Tools. Cursor edits your local project; Replit Agent builds and hosts in the browser; Claude can write and review code in chat or in an editor.
  • Model names. Model versions change quickly.
  • Review. Read generated code, run tests, and watch for secrets and insecure defaults.

8. Claude and LLM Specialist

Lesson 8.1

System prompt optimisation, context window management and artifacts

  • System prompts. State the role, the audience, rules, format and what to do when unsure.
  • Context window. A model can read only so much text at once.
  • Artifacts. In Claude, artifacts are separate documents, pages or small apps produced beside the chat, which you can edit and share.
  • Evaluation. Write 20 test questions and compare prompt versions on them.

Corporate AI audits, ROI models and technology stack mapping
