1. Full-Stack Developer

Lesson 1.1

Foundations of full-stack architecture

  • Client-server model. A client (browser or app) sends a request; a server processes it and sends a response.
  • HTTP protocol. Requests have a method (GET, POST, PUT, PATCH, DELETE), a path, headers and sometimes a body.
  • RESTful APIs. Resources have URLs (for example /users/1) and the HTTP method says the action.
  • GraphQL. One endpoint where the client asks for exactly the fields it needs.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 6

Read more (official sites): MDN Web Docs: HTTP ↗ · Postman documentation ↗

Lesson 1.2

Frontend engineering (React and Next.js)

  • DOM manipulation. The DOM is the live tree of page elements.
  • Component lifecycle. A component mounts, updates when its state or props change, and unmounts.
  • State management. Keep state as local as possible.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 7

Read more (official sites): React documentation ↗ · Next.js documentation ↗ · Zustand ↗ · Redux Toolkit ↗

Lesson 1.3

Backend engineering and databases

  • Node.js and Express. Node runs JavaScript on the server.
  • ORMs: Prisma and Drizzle. An ORM maps database tables to code.
  • PostgreSQL. A relational database: tables, keys, joins, constraints and transactions.
  • MongoDB. A document database that stores JSON-like documents.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 8

Read more (official sites): Node.js ↗ · Express ↗ · Prisma ↗ · Drizzle ORM ↗ · PostgreSQL ↗ · MongoDB ↗

Lesson 1.4

AI-assisted rapid development (vibe coding)

  • What it is. Describing the app in words and letting an AI tool generate code.
  • Tools. Lovable and Bolt generate whole web apps from prompts.
  • Lovable to Supabase workflow. 1.
  • Safety. Never paste secrets into prompts.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 9

Read more (official sites): Lovable ↗ · Bolt ↗ · Cursor ↗ · Supabase documentation ↗

Lesson 1.5

Deployment and DevOps

  • CI/CD pipelines. Continuous integration runs tests on every change; continuous delivery deploys passing builds.
  • Vercel and Render. Vercel suits frontends and Next.js; Render runs servers, databases and background workers.
  • Docker. A container packages the app with its dependencies so it runs the same everywhere.
  • AWS S3 asset hosting. S3 stores files such as images.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 10

Read more (official sites): GitHub Actions ↗ · Vercel ↗ · Render ↗ · Docker ↗ · Amazon S3 ↗

2. WordPress Developer

Lesson 2.1

WordPress core and custom theme development

  • PHP fundamentals. Variables, arrays, functions and conditionals; WordPress runs on PHP.
  • Template hierarchy. WordPress picks the template file by page type: single.php for a post, page.php for a page, archive.php for lists, falling back to index.php.
  • Hooks. Actions run your code at set points (add_action).
  • wp-config security. Keep wp-config.php outside public access where possible, use unique salts, disable file editing (DISALLOW_FILE_EDIT) and never commit credentials.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 11

Read more (official sites): WordPress developer resources ↗ · Theme handbook ↗

Lesson 2.2

Page builders and dynamic content

  • Elementor Pro and Bricks. Visual builders for layouts.
  • Advanced Custom Fields. Adds structured fields (price, date, image) to posts and pages.
  • Custom Post Types. Create content types such as Properties or Courses beyond Posts and Pages.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 12

Read more (official sites): Elementor ↗ · Bricks Builder ↗ · ACF ↗

Lesson 2.3

Automation integration (WordPress and n8n)

  • REST API. WordPress exposes content at /wp-json/.
  • Webhook workflow. 1.
  • Reliability. Verify webhook signatures, return 200 quickly and make the flow safe to run twice.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 13

Read more (official sites): WordPress REST API ↗ · n8n documentation ↗ · Twilio WhatsApp ↗

Lesson 2.4

Speed optimisation and hardening

  • Redis caching. An object cache keeps repeated database results in memory.
  • WP Rocket. A caching plugin: page cache, file minification and lazy loading.
  • Cloudflare CDN. Serves static files from nearby locations and adds protection.
  • Security. Keep core, themes and plugins updated; limit login attempts; use two-factor sign-in; take backups and test restoring them.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 14

Read more (official sites): WP Rocket ↗ · Cloudflare ↗ · Redis ↗

3. Web Developer (vanilla JS and modern web standards)

Lesson 3.1

HTML5 semantic structure and WCAG accessibility

  • Semantic elements. header, nav, main, section, article, footer give meaning to assistive tools and search engines.
  • WCAG basics. Perceivable, operable, understandable, robust.
  • Testing. Tab through the page, use a screen reader, and run an automated checker; automated tools catch only part of the issues.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 15

Read more (official sites): MDN accessibility ↗ · WCAG overview ↗

Lesson 3.2

Advanced CSS3

  • Flexbox. One-dimensional layout: rows or columns with alignment and spacing.
  • Grid. Two-dimensional layout with rows and columns defined together.
  • CSS variables. Custom properties such as --brand store design values once.
  • Animations. Use transitions and keyframes on transform and opacity for smooth results; respect prefers-reduced-motion.
  • Tailwind CSS. Utility classes written in the markup.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 16

Read more (official sites): MDN CSS ↗ · Tailwind CSS ↗

Lesson 3.3

Modern JavaScript (ES6+)

  • Async/await. Writes promise code in a readable order.
  • Fetch API. fetch returns a promise; check response.ok because HTTP errors do not reject.
  • Event loop. Synchronous code runs first, then microtasks (promises), then timers and other tasks.
  • Modules. import and export split code into files with clear dependencies.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 17

Read more (official sites): MDN JavaScript ↗

4. Shopify Developer

Lesson 4.1

Liquid templating engine

  • Tags. Control flow such as {% if %} and {% for %}.
  • Objects. Data such as product, collection and cart, printed with {{ }}.
  • Filters. Change values: {{ product.price | money }}.
  • Schema settings. A JSON block in a section that gives merchants editable settings in the theme editor.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 18

Read more (official sites): Liquid reference ↗ · Shopify theme docs ↗

Lesson 4.2

Custom sections and Shopify CLI workflows

  • Sections. Reusable theme blocks with their own markup, settings and blocks.
  • Shopify CLI. Run the theme locally, push to a development theme and pull changes.
  • Version control. Keep the theme in Git so every change has a history.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 19

Read more (official sites): Shopify CLI ↗

Lesson 4.3

Storefront API and headless commerce

  • Storefront API. Read products and manage carts from your own front end using GraphQL.
  • Headless. The front end is separate from Shopify's theme.
  • Hydrogen and Next.js. Hydrogen is Shopify's React framework for storefronts; Next.js also works with the Storefront API.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 19

Read more (official sites): Storefront API ↗ · Hydrogen ↗

5. Mobile Application Developer

Lesson 5.1

Cross-platform engineering with React Native and Flutter

  • React Native. JavaScript and React; renders native components.
  • Flutter. Dart; draws its own interface with a consistent look across platforms.
  • Choosing. Pick React Native if the team already knows React; pick Flutter for highly custom visuals and one rendering engine.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 20

Read more (official sites): React Native ↗ · Flutter ↗

Lesson 5.2

Native device APIs

  • Camera and GPS. Ask permission in context and handle refusal gracefully.
  • Push notifications. Register a device token and send through a push service; ask for consent and keep messages useful.
  • Offline storage. Store data locally and sync when online; decide how conflicts are resolved.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 21

Read more (official sites): Expo documentation ↗

Lesson 5.3

App store optimisation and deployment

  • ASO. Title, subtitle, keywords, screenshots and ratings influence discovery.
  • Google Play Console. Create the app, upload a signed bundle, complete the content and data-safety forms, test, then release.
  • Apple App Store. Use an Apple Developer account, upload through App Store Connect, add privacy details and pass review.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 22

Read more (official sites): Google Play Console help ↗ · App Store Connect ↗

6. Webflow Developer

Lesson 6.1

Webflow box model, responsive layouts and Client-First naming

  • Box model. Content, padding, border, margin.
  • Responsive layouts. Design for desktop then adjust breakpoints; test on real phones.
  • Client-First. A naming system with consistent class names (for example section_ and u- utilities) so any teammate can edit the project.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 23

Read more (official sites): Webflow University ↗ · Client-First ↗

Lesson 6.2

Webflow CMS, dynamic filtering and custom code

  • CMS collections. Fields, items and collection pages that share one template.
  • Dynamic filtering. Filter lists by category or reference fields.
  • Custom code. Add scripts in project settings or embeds, test them, and avoid loading unneeded libraries.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 23

Read more (official sites): Webflow CMS ↗

7. Frontend Developer (React.js focus)

Lesson 7.1

React hooks

  • useState. Local state; update with the setter, never by changing the value directly.
  • useEffect. Side effects after render; list dependencies carefully and clean up.
  • useContext. Share values such as theme or user without passing props down every level.
  • useMemo and useCallback. Cache a computed value or a function between renders.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 24

Read more (official sites): React hooks reference ↗

Lesson 7.2

SSR vs SSG in Next.js

  • SSG. Pages are built once at build time.
  • SSR. Pages are built on each request.
  • Choosing. Marketing pages and docs suit SSG; dashboards and account pages suit SSR.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 25

Read more (official sites): Next.js rendering ↗

8. E-Commerce Developer

Lesson 8.1

Cart logic, checkout, PCI-DSS and multi-currency

  • Cart logic. Total = items, discounts, shipping and tax in a fixed order.
  • Checkout. Validate stock and address, then create an order before payment is confirmed; confirm only after the payment provider says it succeeded.
  • PCI-DSS. The standard for protecting card data.
  • Multi-currency. Show prices in the buyer's currency with a rate you can explain, round consistently and charge in the currency shown.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 26

Read more (official sites): PCI Security Standards Council ↗

Lesson 8.2

Payment gateway integration

  • Stripe, Razorpay and PayPal. Each provides checkout pages, SDKs and webhooks.
  • Flow. Create an order on your server, open the provider's checkout, receive a webhook, verify its signature, then mark the order paid.
  • Test mode. Use the provider's test keys and test cards; never test with real cards.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 27

Read more (official sites): Stripe docs ↗ · Razorpay docs ↗ · PayPal developer ↗

9. React.js and Next.js Advanced Developer

Lesson 9.1

Next.js App Router, server actions, edge functions and middleware

  • App Router. Folders define routes; layouts nest; server components run on the server by default.
  • Server actions. Functions that run on the server and are called from forms or components.
  • Edge functions and middleware. Run close to the user before a request completes: redirects, auth checks, headers.
  • Security. Treat every server action as a public endpoint.

Read this lesson with its practice task (PDF) · in the full lesson guide, page 27

Read more (official sites): Next.js App Router ↗

Lesson 10.1

Visual database modelling, privacy rules, API Connector and plugins

  • Data types. Model things (User, Order) with fields and relationships.
  • Privacy rules. Control who can find and see each type.
  • API Connector. Call outside APIs with set headers and parameters; keep keys private.
  • Plugins. Use trusted plugins and consider writing your own for repeated needs.
