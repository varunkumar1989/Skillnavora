Subject 1: Python for AI beginners

Subject 1: Python for AI beginners

Covered on the website   Week 1 · Mandatory foundation

1. Understand

Python is a language you write as short, plain instructions. Think of a recipe: each line is one step, and the cook (the computer) follows them in order.

2. Why it matters

Almost every AI tool, library and API example you will meet is written in Python. You do not need to be a programmer to read and change it, but you need the basics.

3. How it works

  • Install Python 3.12 or newer from python.org, then check with python --version.
  • Install VS Code and the Python extension.
  • Learn variables, numbers, strings, lists, dictionaries, if-statements, loops and functions.
  • Use a virtual environment for each project (python -m venv .venv), so libraries do not clash.
  • Keep your code in Git and GitHub from day one.

4. Practical implementation

File: tools/aihandbook/examples/01_calculator.py

# Week 1, Subject 1: variables, input, if-statements, functions
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        return "Cannot divide by zero"
    return a / b

print("2 + 3 =", add(2, 3))
print("10 / 4 =", divide(10, 4))
print("10 / 0 =", divide(10, 0))

Expected output (produced by running the file)

2 + 3 = 5
10 / 4 = 2.5
10 / 0 = Cannot divide by zero

5. Code explained

  • def add(a, b): defines a reusable function with two inputs.
  • return sends a value back to the caller.
  • if b == 0 protects against dividing by zero: a 'guard'. Guards make programs safer.

5b. Deep dive

Think of a Python file as a list of instructions run from top to bottom. Each line either stores a value (x = 5), changes the flow (if, for), or calls a function that does a job. Indentation is not decoration: Python uses it to know which lines belong to a block.

A function is a named, reusable recipe. Write it once, call it many times. Parameters are the ingredients you pass in; return is the dish you get back. A function with no return gives back None, a frequent beginner bug.

A virtual environment (.venv) keeps one project's libraries separate from another's. Create it with python -m venv .venv, activate it, then install with pip install. Commit requirements.txt (from pip freeze) so anyone can rebuild the same environment.

Errors are information. Read the last line of a traceback first (the error type and message), then the line number above it. Use print() or the VS Code debugger to inspect values before guessing.

Subject 2: APIs and backend fundamentals

Covered on the website   Week 1 · Mandatory foundation

1. Understand

An API is a waiter. You (the app) tell the waiter what you want from the kitchen (the server). The waiter brings back the answer in a standard format, usually JSON.

2. Why it matters

Every LLM provider (OpenAI, Anthropic, Google) is reached through an API. Knowing requests, responses and status codes lets you debug any AI integration.

3. How it works

  • Learn the flow: USER -> FRONTEND -> BACKEND -> API -> SERVER -> RESPONSE.
  • Learn the methods: GET reads, POST creates, PUT replaces, PATCH changes part, DELETE removes.
  • Learn the status codes: 200 OK, 400 bad request, 401 wrong key, 429 too many requests, 500 server error.
  • Store secrets in environment variables, never in code.
  • Try an API in Postman, then in Python with the requests library.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Headers carry metadata such as the key (Authorization) and the content type.
  • The body carries the data, usually JSON.
  • A 429 means you hit a rate limit: wait, then retry with backoff.

5b. Deep dive

A request has four parts: the method (GET, POST...), the URL (where), the headers (metadata, such as the key), and the body (the data, usually JSON). A response has a status code, headers and a body.

Status code families: 2xx success, 3xx redirect, 4xx the client made a mistake (400 bad input, 401 missing or wrong key, 403 not allowed, 404 not found, 429 too many requests), 5xx the server failed (500, 503). Log the status and the first 200 characters of the body when an API call fails.

Secrets: never paste an API key into code, a notebook or a chat. Put it in an environment variable (for example OPENAI_API_KEY) and read it with os.environ. Rotate the key if it was ever shared.

Rate limits and retries: providers limit calls per minute and per day. Retry only on 429 and 5xx, wait longer each time (exponential backoff: 1s, 2s, 4s), and stop after a few tries.

Subject 3: LLM and generative AI fundamentals

Covered on the website

Subject 3: LLM and generative AI fundamentals

Covered on the website   Week 1 · Mandatory foundation

1. Understand

A large language model predicts the next word (token) many times over. Like autocomplete on a phone, but trained on a huge amount of text, so the predictions form sentences, code and reasoning.

2. Why it matters

If you know how the model works, you can predict its failures: it can invent facts (hallucinate), forget far-back text (context window limits) and change answers with settings (temperature).

3. How it works

  • Tokens: text is split into pieces. 'Hallucination' may be 3 tokens. Costs and limits are counted in tokens.
  • Embeddings: each token is turned into a list of numbers that places similar meanings close together.
  • Transformers and attention: the model looks at all earlier tokens and decides which ones matter for the next word.
  • Training (pre-training) builds the model; inference is when you use it.
  • Temperature: 0 is focused and repeatable, higher is more varied.
  • System prompt: standing instructions. User prompt: the request. Structured output: ask for JSON.

4. Practical implementation

File: tools/aihandbook/examples/02_json_tokens.py

# Week 1, Subject 4 and 21: dictionaries, lists, JSON
import json

message = {
    "role": "user",
    "content": "Summarise this policy in 3 bullets",
}
conversation = [
    {"role": "system", "content": "You are a helpful assistant."},
    message,
]
text = json.dumps(conversation, indent=2)
print(text)

# A very rough token estimate: about 4 characters per token in English
estimate = len(text) // 4
print("Rough token estimate:", estimate)

Expected output (produced by running the file)

[
  {
    "role": "system",
    "content": "You are a helpful assistant."
  },
  {
    "role": "user",
    "content": "Summarise this policy in 3 bullets"
  }
]
Rough token estimate: 40

5. Code explained

  • json.dumps turns Python objects into text that an API can receive.
  • The 'role' field tells the model who is speaking: system, user or assistant.
  • The token estimate is only a rough guide. Use the provider's tokenizer for exact counts.

5b. Deep dive

Tokens are not words. 'Unbelievable' may split into several tokens. Rule of thumb for English: roughly 4 characters or three-quarters of a word per token, but always measure with the provider's own tokenizer or usage field.

The context window is the model's working memory: instructions, conversation history, retrieved text and the answer all share it. When it fills up, older text is cut off or must be summarised.

Attention lets each token weigh the other tokens. In 'The bank by the river', attention helps the model link 'bank' to 'river' rather than to money. The original paper is Attention Is All You Need (2017).

Temperature rescales the probabilities of the next token. At 0 the model almost always picks the most likely token; at 1 it samples more widely. Top-p limits sampling to the most likely tokens that add up to a threshold.

Hallucinations come from the training objective: predict likely text. A fluent wrong answer is therefore a normal failure mode, not a rare bug. Design for it with sources, refusals and checks.

Subject 4: LLM API integration: your first AI application

Covered on the website   Week 1 · Mandatory foundation

1. Understand

Calling an LLM API is a request-response conversation. You send a list of messages; the model returns one reply. Your app decides what to do with it.

2. Why it matters

This is the smallest possible AI product: input, model, output. Every bigger system (RAG, agents) is this call plus extra steps.

3. How it works

  • Choose a provider and create an API key in its console. Store it in an environment variable.
  • Install the official SDK (for example the openai or anthropic package) and read its current documentation.
  • Send system and user messages. Read the text from the response object.
  • Keep conversation history by appending each message to a list.
  • Handle errors (timeouts, rate limits, invalid keys) and log token usage.

4. Practical implementation

File: tools/aihandbook/examples/03_fake_llm_call.py

# Week 1, Subject 4: the shape of an LLM call, tested offline with a fake model
def fake_llm(messages, temperature=0.0):
    # A real provider returns text generated by a model. This stand-in just echoes the last user message.
    last = messages[-1]["content"]
    return f"(model answer to: {last})"

def ask(question, system="You are concise."):
    messages = [
        {"role": "system", "content": system},
        {"role": "user", "content": question},
    ]
    answer = fake_llm(messages, temperature=0.2)
    return answer

print(ask("What is an API?"))

Expected output (produced by running the file)

(model answer to: What is an API?)

5. Code explained

  • ask() builds the message list: the system message sets behaviour, the user message is the question.
  • fake_llm stands in for the real SDK call, so the lesson works without a key.
  • Swap fake_llm for the real SDK call when you have a key; the rest of the code stays the same.

5b. Deep dive

A chat request is a list of messages with roles. The system message sets rules, the user message is the request, and assistant messages are earlier replies. Keep the list short: send only the turns that matter.

Streaming sends tokens as they are generated. It improves perceived speed; total time is similar. Use it for chat screens; use normal calls for batch jobs.

Structured output: ask for JSON with named keys, validate it in code, and retry or reject if it does not parse. Never trust free text to be parseable.

Cost = input tokens x input price + output tokens x output price. Track both per request, and set a monthly budget alert in the provider console.

Subject 5: Understanding RAG (retrieval-augmented generation)

Covered on the website   Week 2 · Core practical skills

1. Understand

RAG is an open-book exam. Before the model answers, your app looks up the right pages in your documents and hands them to the model with the question.

2. Why it matters

A model only knows what it was trained on. It does not know your leave policy, last week's report or a customer's contract. RAG gives it the right pages at answer time, which is cheaper and easier to update than fine-tuning.

3. How it works

  • Document -> ingestion -> extraction -> chunking -> embedding -> vector database -> retrieval -> LLM -> answer with citations.
  • Use RAG when knowledge changes often or must be cited. Do not use it to teach a new style or skill; that is fine-tuning.
  • Compare with plain search: search returns documents; RAG returns a written answer grounded in them.

# Real systems use an embedding model (a neural network). This toy version counts words,
# so you can see the maths without any API key.
import math, re
from collections import Counter

DOCUMENT = """Employees get 20 days of paid leave per year. Unused leave can be carried forward up to 5 days.
Expense claims must be submitted within 30 days with receipts. Travel is booked through the approved portal.
Remote work is allowed up to 3 days a week with manager approval. Laptops must use disk encryption."""

def chunk(text, size_words=12, overlap=3):
    words = text.split()
    step = size_words - overlap
    return [" ".join(words[i:i + size_words]) for i in range(0, len(words), step)]

def embed(text):
    words = re.findall(r"[a-z]+", text.lower())
    return Counter(words)

def cosine(a, b):
    dot = sum(a[w] * b[w] for w in a)
    na = math.sqrt(sum(v * v for v in a.values()))
    nb = math.sqrt(sum(v * v for v in b.values()))
    return dot / (na * nb) if na and nb else 0.0

def retrieve(question, chunks, k=2):
    q = embed(question)
    scored = [(cosine(q, embed(c)), i, c) for i, c in enumerate(chunks)]
    return sorted(scored, reverse=True)[:k]

chunks = chunk(DOCUMENT)
print("Number of chunks:", len(chunks))

    print(f"score={score:.2f} chunk={i}: {text[:60]}...")

5. Code explained

  • chunk() splits the document into overlapping pieces, so an answer that spans a boundary is not lost.

  • cosine() measures how similar two vectors are: 1 means the same direction, 0 means unrelated.
  • retrieve() ranks all chunks and returns the top k.

5b. Deep dive

RAG has two halves. Indexing (offline): load documents, chunk, embed, store. Answering (online): embed the question, retrieve top-k chunks, build a prompt with them, call the model, return the answer with sources.

Use RAG when the answer must come from a document that changes, must be cited, or is too large for the context window. Use fine-tuning to change style, format or a narrow skill; use prompting first, because it is the cheapest to try.

Common failure: the right chunk is never retrieved, so the model guesses. Measure retrieval recall before you tune the prompt.

Subject 7: Embeddings and vector databases

1. Understand

An embedding is a map coordinate for meaning. Sentences with similar meaning get nearby coordinates, even if they share no words.

2. Why it matters

Keyword search misses 'annual leave' when the document says 'paid time off'. Embeddings find it because the meaning is close.

3. How it works

  • Choose an embedding model from a provider or an open-source model; check its dimension and cost.
  • Store vectors in a vector database (FAISS for local work, Chroma for simple apps, Qdrant or pgvector for production, Pinecone as a managed service).

  • Use hybrid search (keywords + vectors) and a reranker to improve the top results.

Reranking: a stronger model re-scores the top 20 to 50 chunks and keeps the best 3 to 5. It costs time and money, so measure whether it improves answers.

Covered on the website

Subject 9: AI agent fundamentals

Covered on the website   Week 3 · Core practical skills

1. Understand

An agent is a chatbot that can act. It loops: think, choose a tool, look at the result, decide the next step, until the task is done.

2. Why it matters

Many business tasks need several steps across systems (check a balance, book a meeting, send an email). An agent can do the steps; you control which tools it may use.

3. How it works

  • Chatbot: one question, one answer. Agent: a loop of decisions and tool calls.
  • Single agent: one model with tools. Multi-agent: several specialised agents hand work to each other.
  • Human-in-the-loop: a person approves risky actions such as sending money or emails.
  • Memory: short-term (this conversation) and long-term (saved facts, retrieved when needed).
  • Limits: wrong tool choices, loops that never end, and costs that grow with each step.

4. Practical implementation

File: tools/aihandbook/examples/05_agent_loop.py

# Week 3, Subjects 9-10: an agent loop with tools, tested with a scripted "model"
import json

TOOLS = {
    "get_leave_balance": lambda employee_id: {"employee_id": employee_id, "days_left": 14},
    "book_meeting": lambda title: {"status": "booked", "title": title},
}

def scripted_model(history):
    # A real model decides the next step. This script shows the decisions it would make.
    if not any(m["role"] == "tool" for m in history):
        return {"action": "tool", "name": "get_leave_balance", "args": {"employee_id": "E42"}}
    return {"action": "final", "text": "You have 14 days of leave left."}

def run_agent(user_request, max_steps=5):
    history = [{"role": "user", "content": user_request}]
    for step in range(max_steps):
        decision = scripted_model(history)
        if decision["action"] == "final":
            return decision["text"]
        result = TOOLS[decision["name"]](**decision["args"])
        history.append({"role": "tool", "content": json.dumps(result)})
        print(f"step {step + 1}: called {decision['name']} -> {result}")
    return "Stopped: step limit reached"

print("Answer:", run_agent("How much leave do I have left?"))

5. Code explained

  • TOOLS is a registry: the agent may only call functions listed here.
  • max_steps stops a runaway loop.
  • Each tool result is added to history so the next decision can use it.

5b. Deep dive

Agent design questions to answer on paper before coding: what is the goal, which tools are allowed, what is the step limit, what must a human approve, what is logged, and when does the agent stop?

Planning styles: ReAct (think, act, observe in turns), plan-then-execute (write a plan, then carry it out), and router-plus-specialists (one agent picks which specialist handles the request).

Memory: short-term memory is the message history; long-term memory is a store you write to and search later (for example a notes table). Store only what is needed; personal data needs a retention rule.

Limits to test: the agent repeats a failing tool call, invents a tool result, or keeps going after the goal is met. Each needs a guard: step limits, validation of tool results, and a clear stop condition.

print("Answer:", run_agent("How much leave do I have left?"))

  • **kwargs unpacks the model's arguments into the Python function.
  • Errors should be returned as text the model can act on, not crash the app.

5b. Deep dive

A tool schema is a JSON description: name, description, parameters with types and a list of required fields. The description is what the model reads to choose the tool, so write it like instructions for a new employee.

Validation: check every argument (type, range, allowed values) before executing. Reject unknown tools. Return errors as readable messages so the model can correct itself on the next step.

Permissions: separate read tools from write tools. Writes (send an email, change a record, spend money) need an approval step with a person, the proposed action, and a clear yes or no.

Logging: record the tool name, arguments, result summary, user, time and approval for each call. This is your audit trail and your debugging tool.

1. Understand

MCP is a standard plug. Instead of writing a custom connector for every AI app, a service exposes its tools once as an MCP server, and any MCP-capable AI app (the host) can use them.

2. Why it matters

  • Server: the service exposing Tools (actions), Resources (readable data) and Prompts (reusable templates).

Subject 13: AI evaluation

Covered on the website

Subject 13: AI evaluation

Covered on the website   Week 4 · Advanced technical knowledge

1. Understand

Evaluation is a driving test for an AI feature. You prepare a fixed set of questions with known good answers, run the system, and count how many it passes.

2. Why it matters

AI output changes when you change a prompt, a model or a document. Without a fixed test set you cannot tell whether a change made things better or worse.

3. How it works

  • Build a golden dataset: 20 or more questions with the expected answer or a checkable fact.
  • Score each answer: correctness, faithfulness (supported by the context), groundedness, retrieval precision and recall.
  • Automate simple checks (must contain a fact, must cite a source).
  • Use LLM-as-a-judge for subjective scores; check the judge against a few human ratings.
  • Re-run the set after every change (regression testing).

4. Practical implementation

File: tools/aihandbook/examples/06_eval_harness.py

# Week 4, Subject 13: a tiny evaluation harness with a golden dataset
GOLDEN = [
    {"question": "How many paid leave days per year?", "must_contain": "20"},
    {"question": "How many days can leave be carried forward?", "must_contain": "5"},
    {"question": "Who approves remote work?", "must_contain": "manager"},
    {"question": "What is the CEO's salary?", "must_contain": "not in the document"},
]

def system_under_test(question):
    answers = {
        "How many paid leave days per year?": "You get 20 days of paid leave.",
        "How many days can leave be carried forward?": "Up to 5 days.",
        "Who approves remote work?": "Your manager approves it.",
        "What is the CEO's salary?": "The CEO earns 5 crore.",  # a hallucination the test should catch
    }
    return answers[question]

passed = 0
for case in GOLDEN:
    answer = system_under_test(case["question"])
    ok = case["must_contain"].lower() in answer.lower()
    passed += ok
    status = "PASS" if ok else "FAIL"
    print(f"{status}  {case['question']}  ->  {answer}")
print(f"Score: {passed}/{len(GOLDEN)} ({passed / len(GOLDEN):.0%})")

Expected output (produced by running the file)

PASS  How many days can leave be carried forward?  ->  Up to 5 days.
PASS  Who approves remote work?  ->  Your manager approves it.
FAIL  What is the CEO's salary?  ->  The CEO earns 5 crore.
Score: 3/4 (75%)

5. Code explained

  • GOLDEN is the test set. Keep it in version control.
  • must_contain is the simplest checkable rule.
  • The last case is a deliberate hallucination: the harness must mark it FAIL.

5b. Deep dive

Build the golden set from real questions: ask 10 people in the target role for their 5 most common questions, then write the expected answer and the source for each. Include edge cases and questions with no answer.

Metrics: answer correctness (human or judge score), faithfulness (is each claim supported by the retrieved context), context relevance (are the retrieved chunks useful), retrieval recall at k (was the right chunk in the top k), and refusal accuracy (did it decline when it should).

LLM-as-a-judge: a second model scores answers against a rubric. Calibrate it: have a person score 30 answers, then check the judge agrees most of the time. Judges prefer longer answers and their own style, so use a rubric that penalises padding.

Frameworks to explore after the basics: Ragas (RAG metrics), DeepEval (test-style checks), LangSmith (tracing and datasets). Learn the metric definitions first; tools change faster than concepts.

Subject 14: Hallucinations, guardrails and AI quality

Covered on the website

Subject 14: Hallucinations, guardrails and AI quality

Covered on the website   Week 4 · Advanced technical knowledge

1. Understand

A hallucination is a fluent answer that is not supported by the facts. The model is designed to continue text plausibly, not to check truth.

2. Why it matters

In customer support, finance or health, one confident wrong answer can cause real harm. Quality work reduces the chance and limits the damage.

3. How it works

  • Causes: missing context, ambiguous questions, pressure to answer, out-of-date training data.
  • Mitigations: grounding in retrieved sources, citation requirements, refusal when context is missing, confidence signals, fallback answers.
  • Guardrails: input checks (block unsafe requests), output checks (scan for personal data or claims without sources).
  • Prompt injection: instructions hidden in a document or web page that try to override your rules. Treat all retrieved text as untrusted data.
  • Human review: route low-confidence or high-risk answers to a person.

4. Practical implementation

Work through the steps above and keep the result in your portfolio repository.

5. Code explained

  • Refusal is a designed behaviour and must be tested like any feature.
  • Never let retrieved text change the system rules; keep instructions and data separate in the prompt.

5b. Deep dive

Hallucination types: made-up facts, wrong citations, confident answers to unanswerable questions, and mixing two sources into one wrong claim. Measure each type separately; each needs a different fix.

Guardrail layers: input checks (block personal data requests, prompt injection patterns), retrieval checks (minimum relevance score before answering), output checks (every claim has a citation, no personal data in the answer), and human review for high-risk topics.

Prompt injection: a retrieved page may say 'ignore your rules'. Defence: treat retrieved text as data, never as instructions; separate system instructions from data with clear delimiters; limit what tools can do; test with known attack strings.

Confidence signals: retrieval score, the share of claims with citations, and the model's own uncertainty statement. None is perfect alone; combine two and test them on the golden set.

Subject 15: Latency and cost

Covered on the website   Week 4 · Advanced technical knowledge

1. Understand

Every AI request has a price and a waiting time. You pay for tokens in and out, and users wait for the first word and the last word.

2. Why it matters

A feature that is accurate but takes 20 seconds, or costs more than the revenue it earns, will not survive.

3. How it works

  • Measure input tokens, output tokens, time to first token and total time.
  • Reduce cost: shorter context, caching repeated prompts, batching, smaller models for simple steps, model routing.
  • Measure cost per successful task: total spend divided by tasks that met the quality bar.
  • Trade off quality against cost: write the numbers into the PRD.

4. Practical implementation

5. Code explained

  • Output tokens usually cost more than input tokens; keep answers short when short is enough.
  • Streaming improves perceived speed even when total time is the same.

5b. Deep dive

Latency is the sum of parts: embedding the query, the database search, reranking, prompt building, the model's time to first token, and the time for all output tokens. Measure each part with timers before optimising.

Cost levers in order of impact for most products: shorter prompts (trim history, retrieve fewer chunks), smaller models for easy steps (classification, routing), caching identical requests, batching offline jobs, and limiting output length.

Cost per successful task: total spend divided by tasks that passed the quality bar. A cheap model with a 60 percent pass rate can cost more per success than a dearer model with 95 percent.

Set service targets before optimising: for example p95 latency under 8 seconds, cost under a fixed amount per resolved ticket, and quality above the golden-set bar. Optimise only when a target is missed.

8LLMWhat is inference?Running a trained model to produce output for an input.
9PromptingDifference between system and user prompts?The system prompt sets rules and role; the user prompt is the request.
10PromptingHow do you get structured output?Specify a schema, use the provider's structured output or JSON mode, and validate the result in code.
11EmbeddingsWhat is an embedding?A vector of numbers that represents meaning; similar meanings get similar vectors.
12EmbeddingsWhat is cosine similarity?A measure of the angle between two vectors, used to rank semantic similarity.
13RAGWhat is RAG?Retrieval-augmented generation: retrieve relevant passages and give them to the model to answer from.
14RAGWhy does chunk size matter?Too small loses context; too large adds noise and cost and can dilute the answer.

16Vector DBName two vector databases and when to use each.Chroma for simple local projects; pgvector when PostgreSQL is already in use; Qdrant or Pinecone for scale and managed hosting.
17AgentsWhat is an agent?A system that loops: decides an action, uses a tool, observes the result and continues until the goal is met.
18AgentsHow do you stop an agent looping forever?A step limit, a stop condition, cost budget and timeouts, plus logging of each step.
19ToolsWhat is function calling?The model returns a structured request to call a named function with arguments; your code runs it and returns the result.
20MCPWhat is MCP?Model Context Protocol: an open standard that lets AI apps discover and use tools, resources and prompts from servers.
21EvalsWhat is a golden dataset?A fixed, expert-checked set of test inputs and expected answers used to measure every change.
22EvalsWhat is groundedness?Whether an answer is supported by the provided sources.
23EvalsWhat is LLM-as-a-judge and what are its limits?Using a model to score outputs. It is fast, but can be biased; check it against human ratings.
24HallucinationsWhy do models hallucinate?They generate likely continuations, not verified facts; missing context and ambiguous questions increase the risk.
25SecurityWhat is prompt injection?Hidden instructions in input or retrieved text that try to override the system's rules. Treat retrieved text as untrusted data.
26LatencyWhat drives latency in an LLM app?Retrieval time, prompt length, model size, output length and network calls; measure each part separately.
27CostHow do you reduce LLM cost?Shorter prompts, caching, smaller models for simple steps, routing, batching and limiting output length.
28LLMOpsWhat should you log for each LLM request?Prompt and model versions, retrieved sources, token counts, latency, errors and feedback, with personal data removed.
29ArchitectureHow do you design for failure?Timeouts, retries with backoff, fallback responses, a human handoff and monitoring alerts.
30Responsible AIWhat is human-in-the-loop?A design where a person reviews or approves model output or actions, especially for high-risk decisions.
31PythonWhat is the difference between a list and a dictionary?A list keeps items in order and you reach them by position; a dictionary maps keys to values and you reach them by key. JSON objects become dictionaries in Python.
32PythonWhy use try and except around an API call?Network calls fail for reasons outside your code (timeouts, rate limits, bad keys). Catching specific errors lets you retry, show a clear message or fall back instead of crashing.
33PythonWhat does pip install -r requirements.txt do and why pin versions?It installs every listed package. Pinning versions makes builds repeatable, so a new library release cannot silently break the app.
34PythonWhat is async and when does it help in AI apps?Async lets one process wait on many slow input/output calls at once, such as several model or retrieval calls, instead of waiting for each in turn. It does not speed up heavy computation.
35APIsDifference between GET and POST?GET reads data and sends parameters in the URL; POST sends a body to create something or run an action. Model calls are POST requests because the prompt is in the body.
36APIsWhat does HTTP 429 mean and how do you handle it?Too many requests: you hit a rate limit. Back off and retry with increasing delays, respect any retry-after header, and queue or batch work.
37APIsWhat is the difference between 4xx and 5xx errors?4xx means the request was wrong (bad input, no permission); fix the request. 5xx means the server failed; retrying later can work.
38APIsWhat is idempotency and why does it matter for retries?An idempotent request has the same effect if sent twice. Retrying a non-idempotent action such as a payment can do it twice, so use idempotency keys.
39APIsWhat is streaming in an LLM API?The server sends the answer in pieces as it is generated. Users see text sooner, and long requests avoid time-outs.
40LLMWhat is a transformer, in one sentence?A neural network design that uses attention to weigh how much every token in the input matters to every other token, which lets it model long-range context.
41LLMWhat is attention?A mechanism that lets the model look at all earlier tokens and decide which ones matter most for predicting the next token.
42LLMWhy do longer prompts cost more and run slower?You pay per input token, and the model must process every token before answering. Output tokens are generated one at a time, so long answers are slower still.
43LLMWhat is a reasoning (thinking) model and when is it worth it?A model that works through a problem internally before answering. Worth it for multi-step maths, code and planning; wasteful for simple lookups and short answers.
44LLMWhat is effort (or reasoning budget) in modern model APIs?A setting that controls how much the model thinks and how thorough its answer is. Higher effort can improve hard tasks at the cost of latency and tokens.
45LLMWhat is a knowledge cut-off?The date after which the model has no training data. Anything newer must come from retrieval or tools.
46LLMWhat are open-weight models and why choose one?Models whose weights you can download and run yourself. Chosen for data control, offline use, customisation or cost at very high volume; you take on hosting and safety work.
47LLMWhat is fine-tuning good for, and what is it bad for?Good for style, format and narrow repeated tasks. Bad for adding fast-changing facts, which belong in retrieval.
48LLMWhat is multimodal input?A model that accepts images, audio or documents as well as text, such as reading a scanned invoice.
49PromptingWhat is few-shot prompting?Putting a few worked examples in the prompt so the model copies the pattern. Good for format and tone; costs tokens on every call.
50PromptingHow do you write a good prompt for a production task?State the role and goal, give context and data clearly separated (for example in tags), list rules and the output format, show an example, and say what to do when unsure. Then test it on a golden set.
51PromptingWhat is prompt chaining?Splitting a task into steps, each with its own prompt, and passing outputs forward. Easier to test and debug than one huge prompt.
52PromptingWhy separate instructions from data in a prompt?So text inside the data cannot be read as instructions, which reduces prompt injection and confusion.
53EmbeddingsHow are embeddings different from keyword search?Keyword search matches exact words; embeddings match meaning, so 'holiday' can find 'paid leave'. Keyword search is better for exact codes and names.
54EmbeddingsWhat is the dimension of an embedding?The length of the vector, often hundreds to a few thousand numbers. Higher dimensions can hold more nuance but cost more storage and search time.
55EmbeddingsCan you mix embeddings from two different models?No. Vectors from different models live in different spaces. Change model, re-embed everything.
56RAGWhat is hybrid search?Combining keyword (BM25) and vector search results, usually with a weighted merge. It finds both exact terms and paraphrases.
57RAGWhat is query rewriting?Using a model to turn a vague or conversational question into a clear search query, for example adding the subject from earlier in the chat.
58RAGWhat is top-k and how do you pick k?The number of chunks retrieved. Too small misses answers; too big adds noise and cost. Choose by measuring recall and answer quality on the golden set; 3 to 8 is common.
59RAGWhat is contextual retrieval?Adding a short description of where a chunk sits in its document before embedding it, so a chunk like 'It rose 3%' carries its subject.
60RAGHow do you keep a RAG index fresh?Re-index changed documents on a schedule or event, store document versions and dates, and remove superseded chunks.
61RAGHow do you enforce access control in RAG?Store access labels with each chunk and filter by the user's permissions at retrieval time, before anything reaches the model.
62RAGWhen is RAG the wrong choice?When answers need calculation over structured data (use SQL or tools), when the knowledge is tiny and stable (put it in the prompt), or when the task is style rather than facts (prompting or fine-tuning).
63ChunkingFixed-size or recursive chunking: which first?Recursive, because it respects paragraphs and sentences. Measure recall@k before trying anything fancier.
64ChunkingHow do you chunk tables?Keep each row with its header, or rewrite rows as sentences, so a chunk is meaningful on its own.
65Vector DBWhat is an approximate nearest neighbour index?A structure such as HNSW that finds near-best matches very fast by not comparing against every vector. You trade a little recall for a lot of speed.
66Vector DBWhat is metadata filtering?Restricting search to chunks whose metadata matches, such as country or department, before or during the vector search.
67Vector DBCan PostgreSQL be a vector database?Yes, with the pgvector extension. Good when you already run Postgres and need joins, filters and transactions alongside vectors.
68AgentsWorkflow or agent: how do you choose?Use a fixed workflow when the steps are known; use an agent only when the model must choose steps at run time. Workflows are cheaper and easier to test.
69AgentsWhat is the agent loop?The model decides an action, the code runs the tool, the result goes back to the model, and this repeats until the model answers or a limit is hit.
70AgentsWhat is a multi-agent system and its main risk?Several agents with different roles passing work between them. Main risks: cost, loops and errors compounding between agents; add limits and checks.
71AgentsWhat memory does an agent have?Short-term: the conversation and tool results in the context window. Long-term: notes or vectors stored outside and retrieved when needed.
72AgentsHow do you evaluate an agent?Score task success on a set of realistic tasks, plus steps taken, tool-call accuracy, cost and safety violations. Check the trajectory, not only the final answer.
73ToolsWhat makes a good tool definition?A clear name, a description of when to use it, a strict input schema with types and limits, and outputs that are short and structured.
74ToolsHow do you make tool use safe?Least privilege, validate inputs in code, treat outputs as data, require human approval for actions with real-world effects, and log every call.
75ToolsWhat happens if a tool fails?Return a clear error to the model as the tool result so it can try another way, and stop after a set number of failures.
76MCPMCP server versus client?The server exposes tools, resources and prompts (for example a ticket system); the client is the AI application that connects to it and offers them to the model.
77MCPWhat security risks does MCP add?Over-broad permissions, untrusted servers, and injected instructions in tool output. Approve servers, scope credentials and review actions.
78EvalsWhat is the difference between offline and online evaluation?Offline runs a fixed test set before release; online measures live traffic after release (feedback, escalations, sampled reviews). You need both.
79EvalsWhat metrics would you use for a RAG system?Retrieval recall@k, answer accuracy, citation accuracy, groundedness, correct refusal rate, latency p95 and cost per answer.
80EvalsHow big should a golden set be?Start with 30 to 50 real questions covering the main intents and edge cases; grow it with every failure found. Coverage matters more than size.
81EvalsHow do you check an LLM judge is reliable?Compare its scores with human labels on a sample, measure agreement, fix the rubric, and re-check whenever the judge model or prompt changes.
82EvalsWhat is regression testing for prompts?Running the full golden set after every prompt change so a fix for one case does not break others.
83HallucinationsWhat is the difference between faithfulness and correctness?Faithfulness means the answer matches the sources given; correctness means it matches the truth. A faithful answer from an outdated document is still wrong.
84HallucinationsHow do citations help?They tie each claim to a source users can check, and they let you measure whether the cited source supports the claim.
85SecurityWhat is data exfiltration through an agent?Injected instructions make an agent send private data out, for example through a URL or an email tool. Block outbound tools, or require approval, for untrusted contexts.
86SecurityHow should API keys be handled?Stored in a secret manager or environment variables, never in code, logs or the browser; rotated, scoped and monitored.
87SecurityWhat is jailbreaking?Prompts designed to make the model ignore its safety rules. Defend with the provider's safety features, input and output checks, and limited capabilities.
88LatencyWhat is time to first token and how do you improve it?The wait before output starts. Improve it with streaming, a shorter prompt, prompt caching and a faster model.
89LatencyHow does parallelism help?Independent steps, such as searching several sources, can run at the same time, so total time is the slowest step instead of the sum.
90CostWhat is prompt caching?The provider stores a repeated prompt prefix so later calls that reuse it are cheaper and faster. Put fixed content first and changing content last.
91CostWhat is the batch API used for?Non-urgent jobs such as nightly summaries or evals, sent together for a large discount with results returned later.
92CostWhat is model routing?Sending each request to the cheapest model that can handle it, for example a small model for classification and a large one for hard questions.
93LLMOpsWhat is a canary release for an AI feature?Releasing a new prompt or model to a small share of users first and comparing metrics before a full rollout.
94LLMOpsWhat is drift and how do you catch it?A change in user questions or data that lowers quality. Catch it by tracking topic mix, refusal and feedback rates and by sampling conversations weekly.
95LLMOpsWhy pin model versions?So behaviour does not change without your eval running first. Move to a new version deliberately, after testing.
96DeploymentWhy containerise an AI service?The same image runs the same everywhere, with fixed Python and library versions, which makes deploys and rollbacks reliable.
97DeploymentWhat does a health check endpoint do?Gives the platform a cheap way to confirm the service is up, so it can restart or stop routing traffic to an unhealthy instance.
98ArchitectureWhere should guardrails sit in the architecture?At every boundary: input, retrieval, before tools act, and output. No single layer is enough.
99Responsible AIWhat is bias in an AI system and how do you test for it?Systematically worse outcomes for some groups. Test by slicing eval results by language, region or user group and comparing.
100Responsible AIWhat should an AI feature disclose to users?That they are talking to AI, its limits, how to reach a human, and how their data is used.

AI product management

#AreaQuestionModel answer
1StrategyHow do you decide if a problem needs AI?Check whether it needs language or judgement that rules cannot handle, whether data exists, and whether a simpler solution works first.
2StrategyHow is AI PM different from traditional PM?Outputs vary, so quality must be defined, measured and monitored, and failure cases planned for.
3DiscoveryHow would you validate an AI feature idea before building?Interview users, run a manual or wizard-of-oz prototype, measure the task time and accuracy the user needs, then pilot.
4PrioritisationHow do you prioritise AI use cases?Score impact, effort, risk, data readiness and time to value; start with a high-value, low-risk workflow.
5MetricsWhat is a North Star metric for an AI support bot?Resolution rate with safe escalation: correct resolutions per week, which reflects both value and quality.
6MetricsWhich metrics would you track after launch?Task completion, escalation rate, accuracy sample, hallucination rate, cost per task, latency and satisfaction.
7Trade-offsBuild or buy?Compare time to value, three-year cost, data privacy, differentiation and the team's ability to maintain; pilot to decide.
8Trade-offsHow do you choose a model?Start with the cheapest model that passes the golden dataset; upgrade only where quality needs it, and check privacy terms.
9DataWhat data do you need for a RAG product?Documents with owners, permissions, freshness rules and a plan to remove stale content.
10EvaluationHow do you agree a quality bar with stakeholders?Define measurable thresholds per use case, the acceptable error rate, and the human review path for failures.
11Responsible AIHow would you handle a customer's personal data?Minimise what is sent, mask personal data in logs, apply retention rules, and get legal review.
12GovernanceWhat does AI governance include?Use policies, approval for new use cases, risk assessment, audit logs and clear accountability.
13StakeholdersHow do you manage an engineer who says the model cannot do it?Ask what evidence they have, run a small evaluation together, and agree on a test that would change the decision.
14Business caseHow do you calculate ROI for an AI assistant?Hours saved times loaded cost, plus revenue effects, minus build, run and evaluation costs over a set period.
15LaunchHow would you launch an AI feature safely?Limited beta, human approval for risky actions, monitoring, a rollback plan and clear user feedback loops.
16CaseA chatbot gives wrong refund policy answers. What do you do?Contain: restrict or switch off the topic; investigate the retrieved sources; fix the document or prompt; add the case to the golden dataset; monitor.
17StrategyWhat makes a good first AI use case for a company?High volume, clear success measure, low harm when wrong, available data and an owner who wants it. Internal tools often fit before customer-facing ones.
18StrategyHow do you write an AI product vision?Name the user, the job they struggle with, how AI changes it, and the measurable outcome in 12 to 24 months, plus what you will not do.
19StrategyWhat is a moat for an AI product when everyone uses the same models?Proprietary data and feedback loops, workflow integration, distribution, trust and evaluation know-how, not the model itself.
20DiscoveryHow do you find AI opportunities in a workflow?Map the workflow step by step, time each step, find language-heavy, repetitive or judgement steps, and check which have data and tolerate some error.
21DiscoveryWhat is a Wizard of Oz test?Humans pretend to be the AI behind a real interface to test demand and the experience before building the model part.
22DiscoveryHow do you test whether users trust AI output?Watch them use it: do they check sources, edit, or ignore it? Track acceptance and edit rates, and ask what would make them rely on it.
23PrioritisationHow do you size the value of an AI feature?Volume x time saved per task x loaded cost x expected adoption, plus revenue or risk effects, minus build and run costs.
24PrioritisationHow do you say no to an AI feature request?Show the evidence: the problem is rare, a simpler fix exists, the data is missing or the risk is too high. Offer the smaller step you will take instead.
25MetricsWhat is the difference between model metrics and product metrics?Model metrics measure output quality (accuracy, groundedness); product metrics measure user and business results (adoption, time saved, resolution). Good model scores do not guarantee product success.
26MetricsName guardrail metrics for an AI feature.Harmful or wrong answer rate, escalation rate, complaint rate, cost per task and latency p95. They must not get worse while the main metric improves.
27MetricsHow do you measure time saved?Time the task with and without the feature on matched samples, or log task durations before and after, and check quality is the same.
28MetricsWhat does a good AI dashboard show?Volume, quality (eval score and sampled reviews), user feedback, escalation, latency, cost, and splits by version, topic and segment.
29Trade-offsAccuracy versus coverage: how do you decide?Decide by the cost of a wrong answer. High-risk domains answer fewer questions with higher accuracy and refuse more; low-risk ones can answer more.
30Trade-offsLarge model or small model?Start with the strongest model to prove value, build the eval, then test smaller or cheaper options against the same bar.
31Trade-offsPrompting, RAG or fine-tuning?Prompting first; RAG when answers depend on your own or changing knowledge; fine-tuning for consistent style or narrow tasks at scale.
32DataWhat makes documents ready for RAG?A clear owner, current versions, no duplicates, readable text (not scans without OCR), access labels and a refresh process.
33DataHow do you get labelled data for evaluation?Collect real questions from logs or tickets, have experts write expected answers and sources, and add failures from production every week.
34EvaluationWho should own the golden set?The PM owns what good looks like with domain experts; engineers own the harness. Changes to expected answers need review.
35EvaluationWhat is a release bar?The minimum scores a version must meet to ship, agreed in advance, for example 90 percent accuracy and 100 percent correct refusal on unsafe questions.
36Responsible AIHow would you handle a biased output reported by a user?Acknowledge, reproduce, assess impact, contain if needed, fix the data or prompt, add the case to the eval and report the change.
37Responsible AIWhen must a human stay in the loop?When an error is costly or irreversible: money, health, legal, hiring or account changes. The AI can draft; a person decides.
38GovernanceWhat goes into an AI risk register?Each risk (hallucination, data leak, injection, bias, cost overrun, outage), likelihood, impact, owner, mitigation and how it is monitored.
39GovernanceHow do privacy rules such as India's DPDP Act affect an AI product?You need a lawful basis or consent for personal data, purpose limits, minimisation, security, retention limits and a way to handle user requests. Check with legal for specifics.
40StakeholdersHow do you explain AI uncertainty to executives?Use numbers from the eval (for example 92 of 100 answers correct), show examples of the failures, and explain the safeguards and the plan to improve.
41StakeholdersLegal wants to block the launch. What do you do?Understand the specific risk, show the controls and eval evidence, propose a narrower or staged launch, and agree the conditions to expand.
42Business caseHow do you price an AI feature?Base it on value delivered and on cost to serve: include tokens per task at expected usage, set limits or tiers for heavy users, and watch margin.
43Business caseWhat hidden costs do AI products have?Evaluation and labelling, monitoring, human review, prompt maintenance, provider price changes, retries and support for wrong answers.
44LaunchWhat is in an AI launch checklist?Eval above the bar, red-team results, monitoring and alerts, rollback switch, human handoff, user disclosure, support briefed, and a staged rollout plan.
45LaunchHow do you run an A/B test for an AI feature?Randomise users, pick a primary metric and guardrails up front, run long enough for the novelty effect to fade, and check results by segment.
46CaseAdoption of your AI assistant is 10 percent after a month. What do you do?Find out why: discoverability, trust, quality or fit with the workflow. Look at usage funnels and talk to non-users, then fix the biggest blocker first.
47CaseCosts doubled last month. What do you do?Break cost down by feature, prompt version and user; look for longer prompts, retries, heavy users or a model change; apply caching, limits or routing; re-run the eval.
48CaseA competitor launches an AI feature. Should you copy it?Only if it solves a real problem for your users better than your current plan. Check the evidence and your data advantage, then decide.
49CaseDesign a metric framework for an AI meeting summariser.North Star: meetings with summaries used. Quality: rep edit rate, missed action items. Product: weekly active users. Business: time saved and CRM data completeness. Guardrails: privacy incidents, latency.
50CaseYour AI tutor gives a wrong maths answer to a student. Walk through your response.Contain (add a check or disable the topic), investigate the cause, fix, add the case to the eval, communicate with the student and teachers, and track the rate going forward.
